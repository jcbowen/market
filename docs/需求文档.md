# 社区商超多端小程序 - 需求文档

## 一、项目概述

开发一个社区商超多端小程序，支持居民在线浏览商品、加入购物车、下单购买。覆盖多端访问，配套后台管理系统。

### 多端覆盖

| 端 | 技术 | 说明 |
|---|---|---|
| 微信小程序 | uni-app 编译 | 原生微信小程序 |
| 支付宝小程序 | uni-app 编译 | 原生支付宝小程序 |
| Android | uni-app 编译 | APK |
| H5 | uni-app H5 模式 | 含微信服务号访问 |
| 后台管理 | Vue3 + Naive UI | 响应式布局，手机端优先 |

### 2.4 数据模型自动表迁移

各微服务启动时，通过 GORM 的 AutoMigrate 能力自动完成数据库表结构的创建与增量更新，无需手动执行 SQL。

**要求：**

- 每个服务独立管理自身数据模型（Model）定义。
- 服务启动入口统一调用 `AutoMigrate` 方法，注册该服务下所有模型。
- 支持模型字段新增、索引新增等增量变更（GORM 原生能力）。
- 不删除已有字段或数据，避免线上数据丢失。
- 数据库初始化顺序由 docker-compose 健康检查保证，服务启动时若数据库未就绪应重试连接。
- 版本控制中保留模型定义变更记录，便于追溯。

### 2.5 静态文件加载方案

Go 网关通过 Gin 路由加载静态文件：

- `/s/` → 用户端 H5（`bin/static/h5/`）
- `/b/` → 后台管理（`bin/static/admin/`）
- `/api/` → API 接口代理转发
- `/` → 自动 302 跳转到 `/s/`

### 2.6 响应式适配方案（H5）

C 端 H5 主要面向手机端设计，在 PC 及平板设备访问时，因屏幕比例差异会导致页面布局变形。为保证非移动设备下的展示效果，采用 **iframe 嵌套 + 手机外观边框容器** 的方案进行适配。

**适配目标：**

- 移动设备访问时保持原生全屏体验，不显示手机边框容器。
- PC 端及平板设备访问时，居中显示模拟手机外观的边框容器。
- 边框容器固定 18:9 比例（375×750 CSS 像素），完整展示内部页面内容。
- 顶部导航栏、底部 tabBar 等 fixed 定位元素在滚动时保持固定，不随页面内容一起移动。

**实现方案：**

- **双模式入口**：
  - Frame 模式（`index.html`）：非移动设备访问 `/s/` 时返回，负责渲染手机边框、缩放及 iframe 容器。
  - App 模式（`app.html`）：iframe 内部加载的真实 H5 应用入口，渲染原生 uni-app 页面，保持全屏体验。
- **iframe 嵌套**：Frame 模式通过 `<iframe>` 加载 App 模式页面，使内部 `uni-page-head`、`uni-tabbar` 等 fixed 定位元素相对于 iframe 自身视口固定，避免外层 `transform` 缩放导致滚动时一起移动。
- **构建后处理**：`build:h5` 构建完成后执行 `src/client/build-frame.js`，将 uni-app 生成的 `index.html` 重命名为 `app.html`，再将 `src/client/frame.html` 复制为新的 `index.html` 并替换 iframe 加载地址。
- **比例与缩放**：手机边框容器宽度固定 375px、高度 750px，通过 CSS 变量 `--device-scale` 按视口大小等比缩放，确保在 PC/平板屏幕内完整显示，缩放比例不超过 1。
- **夜间模式背景**：PC 端外部背景通过 `prefers-color-scheme` 媒体查询自动切换，非夜间模式为 `#f5f5f5`，夜间模式为 `#1a1a1a`。
- **安全响应头**：Gateway 对 `/s/app.html` 设置 `X-Frame-Options: SAMEORIGIN` 及 `frame-ancestors 'self'`，允许同域 iframe 嵌入。

**相关文件：**

- `src/client/frame.html`：Frame 模式页面模板。
- `src/client/build-frame.js`：H5 构建后处理脚本。
- `src/client/src/static/phone-frame.css`：手机边框容器样式，区分 Frame/App 两种模式。
- `src/backend/gateway/middleware/security.go`：设置允许同域 iframe 嵌入的安全头。

**目录约定说明：**

- `bin/` 是唯一的运行时目录。Go 后端通过 `go build` 输出二进制到此，前端 H5 / 管理后台构建后输出到 `bin/static/`。开发期间启动后端时，以 `bin/` 为工作目录运行；Docker 镜像中 `/app` 目录的内容也来自 `bin/`。
- `pkg/` 仅用于存放 `go mod tidy` 自动下载的第三方依赖缓存（`pkg/mod/`），**不得存放项目自身源码**，且已加入 `.gitignore` 进行过滤。
- `src/backend/common/` 存放后端所有公共包，包括 Protobuf 定义、配置读取、JWT、错误码、响应封装等。
- `src/backend/go.mod` 中的模块路径为 `github.com/jcbowen/market/src/backend`，因此 `src/backend/common/proto/user` 的 import 路径为 `github.com/jcbowen/market/src/backend/common/proto/user`。
- Docker 镜像构建时，构建上下文只保留 `bin/` 与 `src/backend/deploy/`（Dockerfile），其余目录均通过 `.dockerignore` 过滤。

### 4.2 订单状态流转

```
待支付 → 已支付 → 已发货(自提) / 配送中(送货上门) → 已完成
  ↓                    ↓
取消              退款申请 → 已退款
```

- 一笔订单支持多次支付（例如首次支付失败后重新支付、组合支付等），每次支付生成独立支付单。
- 一笔支付单支持多次部分退款，退款金额累计不超过对应支付单金额。
- 退款申请审核通过后，先调用第三方支付退款，成功后再更新订单状态为已退款并释放库存。

### 4.3 支付方式

| 方式 | 场景 | 说明 |
|---|---|---|
| 微信支付 | 微信小程序、H5 | 当 `wechat` 支付 V3 配置不完整时，C 端不展示微信支付选项 |
| 支付宝支付 | 支付宝小程序、H5 | 当前保持关闭状态，仅做配置保存 |
| 现金 | 线下收款，后台标记已支付 | 货到付款/现金支付直接同步订单状态，不经过第三方支付 |

## 五、数据库设计

### 5.1 设计规范

- 所有表使用 InnoDB 引擎，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci
- 主键统一使用 `id BIGINT UNSIGNED AUTO_INCREMENT`
- 时间字段统一：`created_at`、`updated_at`、`deleted_at`（GORM 软删除）
- 金额字段统一使用 `DECIMAL(10,2)`
- 状态字段使用 `TINYINT`，0 表示禁用/删除，1 表示正常
- 索引命名：`idx_表名_字段名`，唯一索引：`uk_表名_字段名`
- 数据隔离：涉及社区的表均含 `community_id` 字段，联合索引隔离

### 5.3 表关系总览

```
users ──┬── user_addresses (1:N)
        ├── carts (1:N)
        ├── orders (1:N)
        └── user_coupons (1:N)

communities ──┬── categories (1:N)
              ├── products (1:N)
              ├── orders (1:N)
              ├── coupons (1:N)
              ├── flash_sales (1:N)
              └── admin_users (1:N)

products ──┬── product_skus (1:N)
           ├── product_images (1:N)
           └── order_items (1:N)

product_skus ──┬── stock_records (1:N)
               ├── carts (1:N)
```

### 7.2 认证鉴权方案

#### JWT Token 设计

- 签名算法：HS256
- Access Token 有效期：2 小时
- Refresh Token 有效期：7 天

**JWT Payload（C端用户）：**
```json
{
  "sub": "1",
  "type": "user",
  "phone": "138****8000",
  "community_id": 1,
  "iat": 1690000000,
  "exp": 1690007200
}
```

**JWT Payload（管理员）：**
```json
{
  "sub": "1",
  "type": "admin",
  "role": "super_admin",
  "community_id": null,
  "iat": 1690000000,
  "exp": 1690007200
}
```

#### 鉴权流程

1. 客户端请求携带 `Authorization: Bearer <access_token>`
2. Gateway 中间件解析 JWT，验证签名和有效期
3. 从 token 中提取用户身份信息，注入请求上下文
4. 后端服务从上下文中获取用户信息，进行数据隔离

#### 多端登录策略

- 同一用户多端登录共享 token（微信小程序、支付宝小程序、H5、Android 使用同一账号）
- 通过 `union_id`（微信）或 `phone`（手机号）关联多端账号
- 首次支付宝登录时，若未绑定手机号，引导绑定手机号以关联微信端账号

#### 权限中间件

- Gateway 层统一校验，区分 C 端用户和管理员
- 管理员接口额外校验角色权限，通过 `role` 和 `community_id` 控制数据访问范围
- 超级管理员（`super_admin`）：`community_id = NULL`，可访问所有数据
- 社区管理员（`community_admin`）：仅访问本社区数据，`community_id` 从 token 获取
- 普通员工（`staff`）：仅访问基础操作权限

#### 缓存更新策略

- **读模式**：Cache Aside（先查缓存，缓存未命中查 DB 并回写缓存）
- **写模式**：更新 DB 后删除缓存（Delete Cache），保证最终一致性
- **热点商品**：启动时预热商品详情到缓存
- **秒杀场景**：活动开始前将库存加载到 Redis，活动期间直接在 Redis 扣减

### 7.8 日志规范

- **日志库**：zap（高性能结构化日志）
- **格式**：生产环境 JSON，开发环境 Console
- **级别**：debug / info / warn / error
- **切割**：按文件大小切割（100MB），保留最近 30 个备份，最长保留 7 天
- **文件命名**：`logs/{service_name}.log`
- **请求日志**：每个 HTTP/gRPC 请求记录 method、path、status、latency、client_ip、trace_id
- **业务日志**：通过 context 传递 `trace_id`，贯穿整个调用链路
- **敏感信息**：禁止记录密码、手机号全号（脱敏处理）

### 7.9 第三方支付对接

#### 微信支付

- 使用 wego 库 `payment/` 包
- 支付方式：JSAPI（微信小程序）、H5 支付（微信服务号）
- 支付流程：
  1. 前端调用 `POST /api/v1/payments` 传入 `order_id` 和 `pay_type=1`
  2. 后端校验微信支付 V3 配置完整性，不完整时直接返回错误
  3. 创建独立支付单（`payment_no` 使用 UUID），通过 wego 调用微信统一下单接口
  4. 返回支付参数给前端，前端调起微信支付
  5. 用户支付完成后，微信回调 `POST /api/v1/payments/callback/wechat`
  6. 后端通过 wego 验签解密，仅处理 `TRANSACTION.SUCCESS` 通知，更新支付单和订单状态
- 幂等性：
  - 支付回调通过 `payment_no` 保证幂等处理
  - 退款通过 `refund_no` 唯一索引保证幂等，重复提交直接返回成功
- 多次支付：一笔订单支持生成多笔支付单，`GetPayment` 返回最近一次支付成功记录
- 多次退款：一笔支付单支持多笔部分退款，累计退款金额不超过支付单金额；支付单累计退完时才标记为"已退款"
- 配置展示：当 `wechat` 支付 V3 配置不完整时，C 端不展示微信支付选项

#### 支付宝支付

- 当前保持关闭状态，不在 `payment.enabled_channels` 中启用
- 保留模拟实现，配置仅保存；如需启用需接入支付宝官方 SDK
- 支付流程：与微信支付类似，回调地址为 `/api/v1/payments/callback/alipay`
- 验签：使用支付宝公钥验证回调签名

#### 现金支付

- 线下收款/货到付款，创建支付单时直接标记为支付成功并同步订单状态
- 不经过第三方支付网关
- 退款时仅记录退款流水，不调用第三方接口

## 九、部署方案

### 9.1 环境依赖

无论是本地开发测试还是生产部署，都需要预先安装以下工具：

| 依赖 | 版本要求 | 说明 |
|---|---|---|
| Docker | 20.10+ | 容器运行时 |
| Docker Compose | v2+ | 服务编排，推荐随 Docker Desktop 一起安装 |
| Go | 1.23+ | 后端编译 |
| Node.js | 18+ | 前端构建 |
| npm | 9+ | 包管理 |

### 9.2 本地启动与测试

#### 9.2.1 一键启动

项目根目录提供了 [start-all.sh](file:///Users/bowen/projects/mine/market/start-all.sh) 脚本，可完成依赖检查、前后端构建、镜像构建、服务启动与测试数据初始化：

```bash
# 常规启动（保留已有数据）
./start-all.sh

# 清理 MySQL/Redis 数据后重新启动
./start-all.sh --clean

# 跳过构建，直接使用已有镜像/二进制
./start-all.sh --skip-build

# 构建镜像时不使用 Docker 缓存
./start-all.sh --no-cache
```

启动成功后，可通过以下地址访问：

| 入口 | 地址 | 说明 |
|---|---|---|
| 管理后台 | http://localhost:18080/b/ | 默认管理员：admin / admin123 |
| C 端 H5 | http://localhost:18080/s/ | 默认用户：13800138000 / 验证码 123456 |
| 健康检查 | http://localhost:18080/health | 返回 HTTP 200 表示网关就绪 |

#### 9.2.2 单独构建与重启

如果只需要修改某一部分，可以单独构建：

```bash
# 构建管理端
cd src/admin && npm run build

# 构建 C 端 H5（会自动执行 build-frame.js 处理 iframe 嵌套）
cd src/client && npm run build:h5

# 构建后端二进制（Linux arm64 交叉编译）
./build.sh

# 重新构建并启动 Docker 服务
docker compose build
docker compose up -d
```

修改前端静态资源后，由于 [docker-compose.yml](file:///Users/bowen/projects/mine/market/docker-compose.yml) 已经将 `./bin/static/admin` 和 `./bin/static/h5` 挂载到 gateway 容器内，因此通常只需要重新构建前端，刷新浏览器即可生效，无需重启 gateway。

#### 9.2.3 常用运维命令

```bash
# 查看所有服务日志
docker compose logs -f

# 查看指定服务日志
docker compose logs -f gateway

# 重启指定服务
docker compose restart product-service

# 进入 MySQL 容器执行 SQL
docker exec -i market-mysql mysql -uroot -pmarket123 market

# 停止所有服务（保留数据卷）
docker compose down

# 停止所有服务并清理数据卷
docker compose down -v
```

### 9.3 生产环境部署

#### 9.3.1 生产环境准备

部署前需要准备：

- 一台或多台 Linux 服务器（建议 2 核 4G 起步）。
- 已备案域名，并解析到服务器公网 IP。
- SSL 证书（可通过 Let's Encrypt 或云服务商获取）。
- 生产级 MySQL 8.0 和 Redis 7 实例（可使用云数据库，也可以自行部署）。
- 微信支付、支付宝支付、短信服务等第三方账号与密钥。

#### 9.3.2 构建发布镜像

在本地或 CI/CD 环境中执行 [deploy.sh](file:///Users/bowen/projects/mine/market/deploy.sh)：


#### 9.3.3 生产配置调整

生产部署前，必须修改 [bin/config.docker.yaml](file:///Users/bowen/projects/mine/market/bin/config.docker.yaml) 中的以下关键项：

| 配置项 | 说明 | 示例 |
|---|---|---|
| `web_server.enable_ssl` | 是否启用 HTTPS | `true` |
| `web_server.cert_path` / `key_path` | SSL 证书与私钥路径 | `/app/ssl/cert.pem` |
| `db.host` / `db.password` | 生产数据库地址与密码 | 云数据库地址与强密码 |
| `redis.host` / `redis.password` | 生产 Redis 地址与密码 | 云 Redis 地址与密码 |
| `jwt.secret` | JWT 签名密钥，必须替换为随机强密码 | 随机 32 位以上字符串 |
| `wechat.app_id` / `app_secret` / `mch_id` / `api_v3_key` / `cert_serial_no` / `private_key` / `notify_url` | 微信支付与登录配置 | 微信官方后台获取 |
| `alipay.app_id` / `private_key` / `alipay_public_key` / `notify_url` / `return_url` | 支付宝配置 | 支付宝开放平台获取 |
| `sms.access_key` / `secret_key` / `template_code` | 短信服务配置 | 阿里云/腾讯云短信平台 |
| `payment.enabled_channels` | 启用的支付方式 | 根据实际接入情况调整 |

#### 9.3.4 生产 docker-compose 调整建议

生产环境建议基于 [docker-compose.yml](file:///Users/bowen/projects/mine/market/docker-compose.yml) 做以下调整：

- 去掉 gateway 对 `./bin/static/admin` 和 `./bin/static/h5` 的宿主机挂载，改为将静态资源打包进镜像。
- 将 MySQL/Redis 替换为云数据库或独立集群，不再使用 docker-compose 内置服务。
- 使用外部网络或反向代理（如 Nginx、Traefik）处理 HTTPS、域名绑定和负载均衡。
- 开启容器资源限制与日志收集。
- 配置数据库定期备份策略。

3. 访问 C 端 H5 `https://your-domain.com/s/` 并验证首页、分类、购物车等核心流程。
4. 测试下单、支付回调、退款等关键链路。
5. 检查各微服务日志是否有异常报错。
