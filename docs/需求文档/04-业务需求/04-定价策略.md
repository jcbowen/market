#### 定价策略
- 商品基础售价维护在商品/SKU 层面：价格落在 SKU（`skus.price`），商品表汇总 `min_price`/`max_price` 供列表展示起售价与价格区间。
- 社区差异化的实际实现路径：**商品与 SKU 本身按社区归属**（`products.community_id`、`skus.community_id`），各社区独立建品、独立维护售价与库存，C 端按当前社区取商品与价格——社区级定价天然由「社区维度的商品数据」承载。
- `community_pricing` 表（`sku_id` + `community_id` + `price`）与 product 服务 gRPC 方法（`SetCommunityPricing`、`ListCommunityPricing`、`GetReferencePricing`，用于跨社区参考定价）已实现服务端逻辑，但**尚未接入**：网关未暴露对应 HTTP 路由、后台无配置页面、商品详情/购物车/下单取价链路均不读取该表（当前一律取 SKU 基础价）。属于预留能力，不作为可用功能描述。
- 划线价只覆盖售价一个维度：`community_pricing` 若启用也仅有 `price` 字段，划线价仍是 SKU 级全局字段，不随社区变化。
- 划线价（`original_price`，0 表示不展示）：
  - SKU 层：`skus.original_price`，后台商品表单按 SKU 行录入（单规格/多规格均可），随 `sku_items` 全量提交保存。
  - 商品层：保存 SKU 时以**最低价 SKU 的划线价**回写汇总字段 `products.min_original_price`，与列表起售价 `min_price` 取同一 SKU，保证「起售价 + 对应划线价」口径一致；商品接口对外只暴露汇总后的 `original_price`。
  - C 端展示：商品详情页售价右侧展示划线价（`original_price > 0` 才渲染），商品列表/分类页仅展示起售价不展示划线价；秒杀列表的划线价取 SKU **当前售价**（`sku.Price`）与秒杀价对照，不使用 SKU 自身划线价字段。
