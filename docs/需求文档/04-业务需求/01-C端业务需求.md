## 四、业务需求

### 4.1 用户端（C端）

#### 用户模块
- 微信小程序授权登录：`uni.login` 取 code，服务端 Code2Session 换 openid，静默建号/更新资料后签发令牌
- 手机号登录：H5 与微信小程序端输入 11 位手机号即可登录/注册（`POST /auth/login/phone`，openid 用 `phone_<手机号>` 占位）
- 手机号验证码：`POST /auth/phone-code` 接口已预留但为测试模式（不调用真实短信服务，登录流程不校验验证码），短信验证码校验待接入。**这是认证入口的上线门禁，当前仅有按 IP 限流与文档化的四步接入动作兜底，详见 `11-开发计划.md`「认证入口上线前置项」第 68 项**
- 支付宝授权登录：未实现（仅接入支付宝**支付**能力：手机网站支付下单、异步回调 RSA2 验签与退款；授权取 openid 的登录链路未开发）。注意支付宝支付本身已实装，网关回调路由 `POST /api/v1/payments/callback/alipay` 处于开启状态，不要按「已下线」理解
- 地址管理（增删改查、设为默认地址；列表按归属社区分组展示）
- 个人资料：在「我的」页点击头像或昵称进入编辑页，可修改头像、昵称、性别、生日；手机号为登录凭证不可修改。未登录时点击该区域跳转登录页
- 登录态静默续期（access_token 2 小时 / refresh_token 7 天，滑动续期）
  - 请求层统一识别 401（HTTP 401 或业务码 11001/11002）：先静默调 `POST /auth/refresh` 换新令牌，成功后重放原请求一次，业务页面无感
  - 并发互斥：同时触发的多个 401 共享同一次刷新请求（模块级单例 Promise），避免并发刷新导致已轮换的 refresh_token 被互相作废
  - 刷新请求自身裸调 `uni.request`，不进入续期逻辑，天然防递归死循环；图片上传（`uni.uploadFile`）同口径「续期 + 重放一次」
  - 刷新成功返回成对新令牌：小程序/App 覆盖本地持久化的 `access_token` / `refresh_token`；**H5 的 `refresh_token` 不在 JS 手里**——登录与刷新由后端下发 httpOnly cookie 承载（请求带 `X-Refresh-Cookie: 1`），前端只覆盖 `access_token`，登出时另调 `POST /auth/logout` 请后端清除该 cookie。分岔原因与属性详见 `07-基础设施/01-端口与认证.md`
  - 仅当确实无法续期（本地无 refresh_token 且无有效 cookie、服务端判定无效/已过期、会员被拉黑）才清空登录态并跳登录页；网络异常保留令牌，下次请求再触发重试
  - 切换社区不重签令牌：令牌中的社区为登录时快照，服务端一律按用户实时归属社区处理（下单、存地址、运费试算）

#### 社区定位
- LBS 定位选择附近社区
- 未登录首次进入自动选择默认社区：系统定位就近选择，失败按出口 IP 定位兜底，再失败取社区列表第一个；**未登录阶段仅写本地缓存不落库**，选中后 toast 轻提示，用户可随时手动切换
- 已登录后的社区绑定落库并本地同步：
  - 登录成功即按登录响应拉取绑定社区的完整信息（含配送费/起送门槛）写入本地；服务端未绑定而本地已有选择（登录前自动/手动选的社区）时，登录页兜底调用切换接口补写服务端绑定
  - App 启动（onLaunch）同样兜底同步：服务端未绑定而本地有选择时补写绑定；本地缓存不完整或绑定社区已失效（拉不到）时，本地社区仍可用则补绑定沿用，否则自动重选并 toast 提示
  - 手动切换社区：已登录同步服务端绑定并同步刷新本地用户信息中的社区字段（避免下次启动被旧值切回），未登录仅更新本地
- 绑定社区停业自愈：启动/回到社区相关页面时校验当前社区营业状态（仅识别显式 `status=0`，兼容无该字段的历史缓存），已停业则自动切换到就近可用社区并提示「已为您切换」；无其他可用社区时仅提示，保留原社区由用户手动处理
- 未选社区拦截（服务端按 `community_id=0` 会拒绝下单/存地址/运费试算，前端提前拦截并引导）：
  - 登录页/App 启动：登录后无绑定社区时兜底补同步或自动选社区
  - 订单确认页：本地无社区信息时提交前 toast「请先选择社区」并引导切换，运费试算静默跳过
  - 地址编辑页：未选社区时顶部提示卡片阻断保存（点击直达社区选择页）
  - 分类页（首页）：进入时本地无社区则取社区列表第一个自动选中（已登录同步服务端，同步失败降级本地选中），无可选社区时终止加载并提示
  - 后端下单前置校验：`community_id<=0` 直接返回「请先选择社区」（区别于 `GetCommunity(0)` 的「社区不存在」误导文案）
- 坐标系：小程序/App 端用 gcj02；H5 端用浏览器原生 wgs84（gcj02 转换需配置地图厂商 key，H5 未配置），wgs84 偏差对就近排序与社区级距离展示可接受；H5 定位要求 https（本地 localhost 除外）
- 社区切换
- 社区列表在系统定位成功时展示与用户的距离（如 850m/1.2km），IP 定位或定位失败时不展示
- 分类页（即首页，见下）展示当前社区商品；购物车按社区分组渲染全部社区的商品，结算一次只针对一个社区（跨社区选中时弹窗选择结算社区，无需切换社区，2026-10-17）

#### 首页（分类页承载）
- 独立首页页面（`pages/index/index`）已下线，首页能力并入分类页：tabBar 仅 3 项——分类页（文案「首页」）、购物车、我的，首个 tab 即启动页
- 外卖式布局：顶部社区切换入口（未选社区时显示「选择社区」并直达选择页）+ 商品搜索栏
- 左侧一级分类导航，右侧按分类分区的商品列表（跨分类无缝滚动，点击左侧分类锚定）
- 分类页顶部 Banner 轮播（见下）
- 底部固定购物车栏：购物车图标与角标、预计金额、去结算；可点开当前社区已选商品弹窗增删数量
- 搜索态：搜索栏展开为输入框，直接展示搜索结果列表（点击取消退出）；关键词为纯数字条形码时同时匹配 SKU 条形码精确命中
- **扫码搜商品**：搜索栏提供扫码入口（仅微信小程序/App 展示，H5 无统一扫码 API 隐藏）；扫码结果为纯数字条码（6-20 位）时走条码精确查询——命中单规格商品直接加入购物车、多规格商品弹规格选择窗、未命中提示并回填关键词；其余扫码内容（如二维码文本）直接当关键词搜索
- **站点页脚**：分类页商品列表滚到底部与「我的」页底部以富文本展示版权与 ICP 备案号（`footer_html`，版权与备案号在后台「站点设置」合并为一个富文本编辑器维护，备案号可配置为指向工信部备案网站的链接），文案取自 `GET /api/v1/site-info`（免登录，服务端已消毒）；未配置时整块不渲染、不占位，接口异常按不展示降级，不报错打断页面

#### Banner 轮播
- C 端仅在分类页（首页）展示 Banner（请求 `GET /banners?position=2`），位于右侧商品列表顶部。
- `position=1`（旧首页位）已无展示位：首页下线后 C 端不再请求，后台仅保留选项用于历史数据显示。
- 后台可配置图片、链接、排序、有效期；点击 Banner 按 link 跳转。
- Banner 表字段：id、community_id、title、image_url、link_url、position（1 旧首页-已废弃 2 分类页）、sort、status、start_time、end_time。

#### 地址管理
- 地址新增/编辑/删除、设为默认地址（默认地址与最新地址优先排序）
- 地址前缀按当前社区裁决：社区未开启「允许社区外配送」时（默认，含未取到社区信息时）锁定为社区省市区，仅可填详细地址，服务端强制覆盖前缀与区划代码；开启外配时自由模式，省市区由区划代码三级联动选择器选择，新增时按出口 IP 预填省/市
- 快捷填写：手机号输入框下方提供快捷候选（登录账号手机号 + 名下其他地址手机号，去重后按已输入前缀过滤、最多 5 个，点击直接填入）；标签提供「家/公司/学校」默认候选，点击填入、再次点击取消
- 编辑页每次展示刷新社区信息（从社区选择页切换返回立即生效，且不重置已填表单）
- 安全：地址查询/更新/删除/设默认均带 `user_id` 归属条件，删除时 `RowsAffected=0` 返回「地址不存在或无权操作」，防止改删他人地址（越权）

#### 商品模块
- 商品分类浏览
- 商品列表（分页、筛选、排序）
- 商品搜索
- 商品详情（多规格/SKU 选择、商品图片）
- 划线价：商品详情售价右侧展示划线价（`original_price > 0` 才展示，0 表示不展示）；商品级划线价取最低价 SKU 的划线价，与列表起售价口径同一 SKU
- 秒杀商品列表划线价为 SKU 当前售价（与秒杀价对照），非 SKU 自身划线价字段
- 分类页快速下单：单规格商品点击加号直接加购；多规格商品弹出规格选择窗，规格数据由商品详情接口兜底加载，选中完整规格后加入购物车，选中规格展示对应规格图片

#### 购物车模块
- 添加商品到购物车
- 修改商品数量/规格
- 删除商品
- 全选/批量操作：按社区分组独立全选，跨社区商品互不联动；底部结算栏只汇总当前结算社区
- 跨社区购物车（2026-10-17）：购物车页渲染全部社区的商品（按社区分组）；结算一次只针对一个社区——单社区选中直接结算，跨社区选中时弹窗选择本次结算的社区，无需切换社区；确认订单页（自提点/运费/满减/试算/下单归属）均按所选结算社区计算
- 未登录使用本地缓存购物车（按社区分组），登录成功后逐条同步到服务端购物车并清空本地（单条失败不影响其他商品）
- 购物车页底部「常买商品」区块：按历史有效订单统计的常买商品，可一键加购（口径见订单文档）
- 起订份数：商品可配置最低购买份数 `min_buy`（默认 1）；C 端下单逐行校验数量 ≥ `min_buy`，不足返回「商品 X 最低购买 N 份」。收银台代客下单（`source=2`）豁免该校验，便于现场按实际称重/拆零收款

#### 订单模块
- 下单（选择地址、备注、优惠券）
- 取货渠道按社区配置渲染：社区关闭自提/配送时对应按钮隐藏，仅剩一种方式时自动切换；服务端同口径兜底拒绝
- 支付（微信支付 / 支付宝支付 / 现金）
- 订单列表：展示所属社区标签（订单号仅在订单详情展示）；跨社区订单可辨识
- 订单详情：点击商品行跳转商品详情页
- 优惠券确认页体验（2026-10-17）：进入确认订单页自动选中抵扣金额最大的可用券；点开优惠券弹窗列出全部未使用券，不可用的置灰并展示原因（已过期 / 满 X 可用还差 Y）；手动选择后不再自动改选
- 取消订单
- 删除订单（2026-10-23 新增）：仅终态订单（已完成/已取消/已退款）在列表提供「删除订单」入口，二次确认后软删除——从 C 端列表与角标统计中移除且不可恢复；存在进行中售后（待审核/退款中）时不可删；订单详情与后台管理不受影响，售后进度/支付详情链路仍可达
- 退款申请（2026-10-23 交互升级）：弹窗内默认整单退，可取消勾选或调低数量改为部分商品退；金额以服务端按实付汇算为准（仅允许调低），整单退按社区运费退还策略（始终退/不退/用户自行选择）处理；提交后进入待商家审核
  - 退款原因：常见理由标签快选（不想要了/拍错了/商品与描述不符/商品质量问题/商品破损或漏发/少发货/发货太慢），选「其他」时补充输入
  - 退款金额卡片：置于商品明细之后（合计应退大字突出 + 商品/运费分项 + 调低输入与「重置」快捷恢复）
- 退款进度查看（2026-10-23 新增）：退款中/已退款订单详情显示「退款进度」入口，弹窗按退款单时间线展示（提交申请 → 商家审核 → 退款处理 → 已到账）；已拒绝单展示拒绝原因；提示退款原路返回，到账以支付渠道为准（一般 1-3 个工作日）
  - 时间线的完成态按**显式「状态 → 步数」映射**渲染（`RefundProgressModal.vue` 的 `REFUND_STEP_BY_STATUS`，2026-10-24 C1）：退款状态码是枚举不是进度计量，`3已拒绝` 就插在 `2已同意` 与 `4退款中` 之间，用 `status >= N` 比序数在后端新增状态码时会让整条时间线错乱。未知状态码只画「提交申请」一步——宁可少显示进度，也不凭猜想把后续步骤画成已完成
- 门店订单（收银台代客，`source=2`）在 C 端展示但只读：隐藏取消/退款/确认收货/去支付按钮，服务端同口径拒绝

#### 配送方式
- 社区自提（取货码核销：订单详情展示取货码，到店由履约人员/后台核销，C 端不可自行确认收货——决策点⑤）
- 送货上门（自配送模式：后台可传统物流发货，或指派履约人员由 C 端履约工作台配送）

#### 履约工作台（B）
- 会员管理中将某会员设为本社区「履约人员」后，其「我的」页出现履约工作台入口
- 送货模块：仅展示指派给本人的配送单（进行中/已完成），支持「开始配送」（status 2/3→4）与「送达拍照」（status 4→5，**强制上传 1~3 张签收照片**，决策点②），C 端订单详情可查看签收凭证
- 自提核销模块：展示本社区待核销/已核销自提单，输入顾客出示的 8 位取货码核销（防错领/冒领；服务端校验社区归属与重复核销）
- 鉴权：所有工作台接口实时校验当前用户在其归属社区是履约人员，取消身份后入口与接口立即失效

### 4.2 订单状态流转
