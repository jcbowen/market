### 4.4 后台管理端

#### 商品管理
- 商品分类管理（多级分类）：物理删除前校验商品引用，仅统计**未软删**（`status<>2`）的商品——已下架删除的商品不再可售也不出现在任何列表，不应永久卡住分类删除
- 商品 CRUD
- 起订份数（`min_buy`，商品级，默认 1）：C 端下单逐行校验数量 ≥ `min_buy`；收银台代客下单（`source=2`）豁免，便于现场拆零/称重收款
- 商品上下架
- 多规格/SKU 管理（SKU 规格图片支持后台上传，C 端选中规格时展示对应图片）
- SKU 划线价（`original_price`，原价，0 表示不展示）：单规格与多规格 SKU 行均可录入，随商品创建/更新的 `sku_items` 全量提交（网关 `toProtoSkuItems` 透传至 product 服务）
- 商品划线价汇总：保存 SKU 时以最低价 SKU 的划线价回写商品 `min_original_price`，与列表起售价（`min_price`）取同一 SKU，C 端详情/列表按该汇总值展示划线价
- **商品条形码**（挂 SKU 级，单规格表单与多规格 SKU 列表均可录入，支持扫码枪直接录入）：纯数字 6-20 位宽松校验（不做 EAN 校验位强校验）；同社区内在售 SKU 间唯一，重复返回 10001 并提示占用商品名；商品软删后条码自动回收可复用；条码精确查询 `GET /admin/products/barcode/:code`（命中返回商品 + 具体 SKU）
- **SKU 价格与成本校验（2026-10-26）**：划线价一旦填写不得低于本行售价（0 仍表示「不展示划线价」，允许），否则 C 端展示成「优惠为负」的误导信息；成本价不允许为负——毛利报表按 `cost_price` 汇算，负成本直接污染报表。规格组合重复、同商品内条码重复沿用既有拦截
- **SKU 归属以商品为准（2026-10-26）**：独立 SKU 接口（gRPC `CreateSku`/`UpdateSku`，后台无对应 HTTP 端点，仅内部或直连可达）先校验商品存在、未软删且在当前社区范围内，落库的 `community_id` 取商品的值而非入参——此前可造出「他社区商品 + 本社区 SKU」的漂移行，而 SKU 搜索按 SKU 社区过滤，会把别社区的商品名带进本社区结果
- **商品汇总列回写口径（2026-10-26）**：`products` 的 `min_price / max_price / min_original_price / stock` 四列由唯一函数 `syncProductAggregates` 按**启用 SKU（`status=1`）**实时聚合回写；调用点为规格保存、单 SKU 新建、单 SKU 编辑三条价格链路，以及扣减/回补、入库、出库、盘点四类库存交易链路，全部在同一事务内完成。全部 SKU 禁用或软删时汇总列归 0（避免残留旧值把无货商品判成「有货」）。后台商品列表的「已售罄 / 库存紧张」Tab 与状态统计直接读 `products.stock`，交易链路不回写即长期失真；服务启动另有兜底对账（只校正实际不一致的行，可重复执行）
- **列表分页服务层上限（2026-10-26）**：HTTP 网关已按 `maxPageSize=100` 收敛，gRPC 服务侧再设 200 硬上限——内部或直连调用传超大 `page_size` 不允许退化成全表拉取
- **后台列表翻页与查询重置（2026-10-26）**：商品列表、盘点单列表、采购供应商列表等补齐 `@update:page` 接线（此前表格只切页码、数据仍由服务端按第 1 页返回，点第 2 页看到的还是第 1 页内容）；库存工作台三个页签、出入库报表、批次选择器的「查询」与回车搜索统一把页码归 1（停在第 3 页改关键词会命中空列表）
- **商品富文本详情（2026-10-27）**：商品编辑页提供富文本编辑器维护图文详情（`products.content`，`mediumtext`），C 端商品详情以 `rich-text` 渲染
  - 服务端白名单消毒（`service/sanitize.go` 的 `SanitizeProductContentHTML`）：允许 `p/br/b/strong/i/em/u/span/div/h1~h6/ul/ol/li/img/a`，`img` 仅留 `src/alt/width/height`、`a` 仅留 `href/title` 且强制新窗口打开；`script/style/iframe/object/embed/noscript/template/svg/math/form/input/button/textarea/select` **连子树整体丢弃**（其文本内容同样是攻击载荷）；其余非白名单标签解包保留子内容；`style`/`class` 等展示属性一律剔除防 CSS 注入；文本节点一律 HTML 转义，防存储型 XSS
  - `img.src` 与 `a.href` 经 `safeContentURL` 校验：只放行站内相对路径与 http(s) 外链，`javascript:` 等危险协议剔除
  - 性能口径：`content` 是大字段，列表查询一律 `Omit("content")`，只有详情与编辑回显才读取（详见 05-数据库设计/03 的 `products` 表说明）

#### 库存管理
- **商品入库（2026-10-30 修订）**：采购入库/直接入库走入库单（记录入库时间、保质期、批次号；支持 `biz_no` 幂等重放）；**退款退货不生成入库单**——退款链路经 `ReleaseStock` 自动回补批次与汇总库存（流水 `ref_no=退款单号`，与取消回补同槽位口径）
- **商品出库（2026-10-30 修订）**：销售出库由订单扣减链路自动产生（FEFO 取批次）；报损/领用/调整走手工出库单。**过期批次处置：仅销售拦截**——销售扣减跳过过期批次（全部过期时拒 12002「无可用（未过期）批次库存」），报损/领用/调整与盘点盘亏不拦截（过期品靠这些渠道消耗出库）
- **库存盘点**：定期/不定期盘点，记录盘点差异，生成盘点单
- **库存预警**：低库存预警（低于安全库存）、保质期临期预警
- **库存流水**：所有库存变动记录，可追溯查询
- **一键生成补货单**：根据库存预警自动生成补货建议
- **单据号生成口径（2026-10-26）**：采购单/入库单/出库单/盘点单统一走 `generateBillNo`——前缀 + `yyyyMMddHHmmss` + 6 位随机后缀。旧口径取 `Nanosecond()/1e5`（100µs 粒度），同一秒内并发建单会撞号：盘点单号本就带唯一约束（`unique` tag），撞号直接 1062 报错建单失败；采购/入库/出库单号只有普通索引，撞号后两张不同单据同号，对账与追溯无法区分。**明确取舍：不给 `purchase_no/in_no/out_no` 补唯一索引**——存量数据可能已存在重复行，补索引会让 AutoMigrate 在建表阶段失败并导致服务启动崩溃，代价高于收益，消碰撞交给随机后缀即可
- **盘点提交口径（2026-10-26）**：服务端对盘点单头加行锁（`FOR UPDATE`，与采购/出入库同口径），提交完成用条件更新 `WHERE id=? AND status=1` 做二次守卫——命中 0 行说明单据在锁等待期间已被并发提交或撤销，返回「盘点单状态已变更，请刷新后重试」；明细拒绝负数实盘与同单重复 SKU（重复行的「系统库存」会被前一行的改动覆盖，差异与品项统计双双失真），空明细直接拒绝。**实盘 0 是合法结果**（该 SKU 已清空），网关入参用 `*int32` 接收——非指针 `int32` + `binding:"required"` 会把 0 判成「未填」，导致零库存永远盘不掉；前端「提交盘点结果」增加二次确认（本次盘点 N 个 SKU、提交后立即按差异调整且不可撤销）。并发提交与差异调整后同样回写商品汇总列
- **入库/出库联动**：两条链路在同一事务内完成批次与流水写入后回写商品汇总列；批量取 SKU 简介/商品名失败时降级为「单据缺商品名」并落 `[WARN]` 日志，不再静默吞错
- **采购单提交（2026-10-26）**：表单「提交」建单时带 `submit_now=true` 已由服务端直接置为已下单，前端不再二次调用提交接口（此前草稿已提交后再次提交会报错并中断跳转），提交成功统一跳转采购单详情

- 订单详情（含物流信息展示与按状态渲染的操作按钮）
- **售后记录区块**：逐条展示本单每次退款（退款单类型「整单退/部分退/金额退」标签、退款金额并标注含运费金额、退款商品明细「商品名(规格)×数量」，仅金额退显示「不退商品」、**订单本身无商品行（`order_item_count=0`，收银台直接收款单）显示「无商品明细（直接收款）」**、退款单状态标签、退款原因/退款时间），无售后记录时区块不渲染；**「无商品明细」按订单口径（`order_item_count`，proto 数字 0 会被省略，前端统一 `?? 0` 归一）判定，不看本退款行有无 `items`**——仅金额退在全额退完时同样升为整单退（type=1）且没有明细，误判会把普通单标成直接收款；与售后管理页同源数据；**行内审核（2026-10-23）**——待审核售后单在操作列直接提供「同意/拒绝」（逻辑与售后管理页一致：同意二次确认、拒绝原因必填），免关单跳转售后管理页
- **无商品单展示（2026-10-25）**：订单详情商品明细为空时（收银台直接收款单）展示「该订单无商品明细（直接收款）」空状态，不再渲染空白表格；订单导出商品明细列输出「直接收款（无商品）」。
- 订单列表/详情展示支付方式（pay_type：微信/支付宝/货到付款/现金）；**支付方式图标化（2026-10-25）**：以渠道品牌色图标展示（微信=绿色气泡/支付宝=蓝色/现金=橙色钞票/付款码=扫码/货到付款=钱包图标），**列表仅图标**（桌面悬浮/触屏点按经 tooltip 显示文字，2026-10-25 修订），详情弹窗图标+文字；后台与收银台订单查询共用 PayTypeLabel 组件，未接入渠道或待支付单仅显示文字
- 发货操作（仅配送单；物流公司/单号必填，写入独立字段）
- 自提核销（自提单已支付后直接「核销完成」，无需发货）
- 取消订单（取消原因必填，取消后整单回补库存并回补订单占用的优惠券）：**回补动作在本地取消事务提交之后执行（2026-10-26 修订）**，不在事务内——远端 product 服务已提交的回补无法随本地事务回滚，早期把回补放在事务内会出现「事务回滚、订单仍待支付，货却已放走」的一物两卖；方向相反的失败（提交后回补调用失败）只是少卖，安全。回补走批量接口（整单明细一次往返、同一事务）并以 `cancel:{订单号}` 为幂等槽位，脱离调用方取消信号（`context.WithoutCancel`）+ 有限重试 + 超时预算，最终仍失败则落 `scheduler_failures`（`task_type=cancel_release`）由调度器自动重放（上限 5 次）；后台取消入口的口径与服务端一致——待支付单（任意支付方式）+ 货到付款未发货单（2 已支付/3 备货中）；配送中及之后走退款流程；门店单后台路径不做额外限制（只读控制仅在 C 端）
- 批量发货（选中配送单共用同一物流信息）与批量核销；订单导出改为**后台异步 CSV（2026-10-24）**：点「导出 CSV」创建任务立即返回（沿用当前筛选条件，所见即所导；单次上限 10 万行，超限截断并提示缩小范围），生成完成后在**右上角下载中心**取文件。**下载中心**（布局右上角下载图标）：弹出面板展示近 3 天任务（文件名/条件摘要/状态「排队中·生成中·已完成·失败」/大小/行数/生成时间），文件生成后保留 **3 天**到期自动清理（文件+记录）；有已完成未下载的文件时图标显示数字角标；下载留痕（次数/下载人/时间）；记录可见性——普通管理员仅见自己创建的，超管见全部并可删除任意记录（删除时文件一并删除）；下载走网关鉴权接口流式下发，不走公开静态目录——`uploads/exports/**` 在网关静态路由上固定返回 404，避免可枚举的导出直链（详见 07-基础设施/03-缓存存储与日志.md 的「导出文件为私有区」）
- 退款审核处理（C 端申请单：同意/拒绝；退款中卡单支持「重试退款」；审批动作落 refund_logs 日志）。**卡单自动重试的边界（2026-10-24）**：调度器按节流指针轮转核查，累计 24 次仍未收敛的单停止自动重试并落 `action=give_up` 轨迹（展开行显示「停止自动重试（转人工）」），同时支付侧的退款流水也会因连续查单失败（上限 10 次）退出自动收敛批次——两侧预算各自独立，所以处置必须一次动作两侧都改。**两个卡单出口按「碰不碰钱」区分（2026-10-24 B2）**：「重试退款」再次向渠道发起出款（要求支付侧流水已判失败或不存在，否则会回「退款处理中，请勿重复提交」）；「恢复自动收敛」只把支付侧 `retry_count/escalated` 与订单侧 `retry_count/last_checked_at` 归零、让系统重新去核实渠道终态，全程不触渠道、不动钱，是「微信退款 1-3 个工作日才到账、但系统已放弃收敛」这类死角的唯一出路。两者都要求先人工核实渠道事实，恢复收敛还必填核实依据（落 `refund_logs.action=reset` 的 remark 与 `payment_notify_logs` 的 `kind=7/result=11` 留痕，并顺带销掉该退款单此前的转办待办）；不允许直接改状态。**审核语义（2026-10-23 确认）**：同意=按申请金额全额退回原支付流水，同意时不提供修改退款金额入口——保持「同意=全额退、拒绝=不退」的简单语义；商家希望少退时走「拒绝 + 订单详情『退款』按钮主动部分退（免审核按金额执行）」组合覆盖
- 代客退款（后台/收银台发起，**免审核**：创建即置退款中并调用渠道退款，成功后统一收尾）：三种方式——整单退、部分商品退（勾选商品行与数量）、仅金额退（不退商品、不回补库存），金额默认服务端按实付汇算、可调低，整单退按运费策略决定是否退还运费；**无商品明细单（直接收款）只保留整单退/仅金额退，整单退按剩余可退金额执行且不产生退款明细**；详见《订单与支付》4.2.2

- 站点设置（读 `settings:view`，写 `settings:update` + 仅超管；平台配置组首项）：平台级品牌与**部署域名的唯一来源**
  - 分区：部署域名 / 派生地址（只读）/ 品牌信息（站点名称、logo、favicon 各自独立字段）/ 页脚与备案 / 搜索优化

  - `base_url` 只填 `scheme://host`（服务端归一并拒绝带路径参数者），派生出微信与支付宝异步通知地址、支付宝支付完成回跳地址，以及附件外链与 HTML 注入用的绝对地址
  - 生效优先级：站点设置 `base_url` > 环境变量 `SITE_BASE_URL`（兜底默认值，未配置时站点设置页回填该值）> 按当前请求现推；页面回显当前生效域名与其来源，内网/环回地址给出「回调不可达」告警。**注意第三档「请求现推」只用于前台品牌展示与外链拼接，回调地址一律不取它**（否则谁先访问就把谁的临时域名固化成配置，见支付配置条目）
  - 品牌字段（站点名/logo/favicon/版权/备案号/SEO 描述与关键词）由网关在返回前端 HTML 入口时注入 `<title>`、favicon、description/keywords 与 `og:*`，浏览器与搜索引擎爬虫读到同一份内容；配置取网关内存快照（TTL + `version` 驱动失效），不逐请求查库
  - 后台左侧菜单底部、登录页与「关于系统」页脚展示版权与备案号（富文本 HTML）；站点名称用于品牌位（与社区门店名分层，二者不混用）
- 渠道管理（`settings:view`/`settings:update`，仅超管）：维护 7 个内置客户端渠道（h5/gzh/mp/alimp/android/ios/pos，2026-10-30 重构）的 AppID/AppSecret、启用状态与**支付方式绑定**（弹窗「支付方式」区块：有序勾选各端可用的支付配置与内置货到付款，↑↓ 即收银台顺序）；渠道名称与 code 为内置固定只读（弹窗内仅展示不可编辑，服务端忽略传入名称）；列表启用渠道在前、停用在后，组内按固定常用顺序（切换开关后启用的渠道自动前置）；android/ios 为禁用态卡片（App 支付 SDK 未接入），pos 无凭证恒启用；卡片为左右布局，右侧统一「扫码访问」区——H5 基于站点设置生效域名（`{base_url}/s/`）纯前端生成站点二维码（`qrcode` 包，点击弹窗放大/复制链接/打开页面），未配置域名时展示引导并跳转站点设置；小程序与公众号展示公众平台获取二维码的指引；各卡片扫码区占位一致，避免视觉突兀
- 支付配置（`settings:view`/`settings:update`）：按平台分组的**多行配置列表**（同平台可多条、独立启停，无渠道勾选——渠道启用哪些配置改在渠道管理侧绑定）；微信/支付宝参数、商户证书上传；回调地址（微信/支付宝异步通知、支付宝回跳）为**只按显式部署域名派生的只读值**（来源仅站点设置 `base_url` 或环境变量 `SITE_BASE_URL`，**不含按请求现推的域名**），本页不再手填，前端提交的回调地址一律被忽略；未配置显式域名时落库为空串，该配置行由就绪判定拦为未就绪并给出「缺少异步通知地址」原因；站点设置保存时域名与回调地址**同进退**——填写即覆写为派生值、清空即回收为空串，不把上一个测试域名残留在库里；回写只由「保存站点设置」与「保存配置行」两个动作触发，读取配置不写库；删除配置前校验无渠道引用
- 售后配置（`settings:view`/`settings:update`）：整单退时的运费退还策略（always 始终退 / never 不退 / user_decide 由用户选择），以及**已完成单售后窗口** `completed_refund_hours`（默认 168 小时=7 天，0=关闭已完成单自助申请入口），保存即时生效、无需重启；入口在系统空间「系统管理」菜单（仅超管）
- 平台验证文件（站点设置页内分区，读 `settings:view`、写 `settings:update` + 仅超管；2026-10-31 新增）：微信域名归属校验文件管理——公众号「JS接口安全域名/网页授权域名」需上传 `MP_verify_xxx.txt`（内容为纯文本 token）、小程序「业务域名」（web-view 内嵌 H5）需上传随机名 `.txt` 校验文件（内容为 JSON 串），两者都必须能通过 `https://域名/文件名.txt` 直接访问到与原文件一致的内容；**支付宝小程序无需验证文件**（web-view 仅在开放平台配置 H5 白名单），本功能平台无关、其他平台可复用
  - 交互：文件名输入框**不填后缀**（`.txt` 以输入框内嵌后缀展示）+ 内容 textarea 粘贴平台校验文件原文（用文本编辑器打开下载的 .txt 复制），保存即在网关落盘真实文件；列表展示完整文件名（点击可打开访问）、大小、更新时间，支持「填入表单」回填文件名与删除（删除确认提示域名校验立即失效）
  - 实现口径：文件落盘网关运行目录 `verify/`，站点根路径**伪静态下发、零查库**——响应字节级原样、固定 `text/plain` + `nosniff` + `no-cache`，纯静态无任何执行面；文件名白名单 `[A-Za-z0-9._-]` ≤64 字符（后端强制补 `.txt`）、内容 ≤64KB、文件数 ≤20；容器重建后文件丢失属预期（验证文件可随时重新生成），不持久化到数据库
- 附件配置（`settings:view`/`settings:update`）：存储模式（本地 / 阿里云 OSS，预留 COS），OSS 预签名 URL 直传 + MD5 秒传；本地附件迁移工具入口在此页（路由 hidden，不进菜单）

#### 权限与菜单渲染（与 RBAC 实现对齐，详见《权限与数据隔离》）
- 权限模型为**权限点级 RBAC**，不是固定三级角色：账号（`admin_users`，含 `is_super` 标记）与「社区任职」（`admin_communities`：管理员 × 社区 × 角色，可多社区多角色）分离，角色（`admin_roles`）按社区归属区分全局角色（`community_id=0`）与社区私有角色
- 权限点命名 `模块:动作`（如 `product:view`、`order:create`、`refund:update`、`community:config`），清单集中在 `src/admin/src/constants/permissions.ts` 按模块分组维护；`*` 为通配全量
- 前端路由守卫按 `meta.permission` 判定（无权限保留登录态跳 `/403`，权限为空才登出兜底），左侧菜单按权限点 + `superOnly` 过滤，页面内按钮再按 `hasPermission` 控制（如附件配置的 `settings:update`）
- 后端网关每条管理路由挂 `RequirePermission("xxx")` 中间件：非 `admin` 类型令牌直接拒绝；超管放行；其余按（管理员 × 当前社区）**实时**解析任职角色权限并集，再与该社区的权限上限取交集，命中所需权限点之一即通过
- 收银台独立应用（`/pos`）页面同样按 `order:create` 判定，未选定社区时先跳社区选择页

#### 应用中心与数据导入（2026-10-27）
- 应用中心（`/apps`，登录即可见）：宫格式应用入口，应用在 `src/admin/src/constants/apps.ts` 的 `APP_REGISTRY` 注册——收银台（`/pos/cashier`，要求 `order:create`）、数据导入（`/apps/data-import`，要求 `product:create` 且仅超管，非超管不展示卡片）
- 数据导入（`/apps/data-import`，仅超管）：把固化的演示数据包按条目导入**当前社区**，用于新环境起量或补演示数据
  - 三段式：选包（列出可见段与条目数）→ 预检（逐条目给出 `create`/`skip`/`depend_missing` 与默认勾选）→ 执行（返回 created/skipped/failed 与逐条结果）
  - 可导段：商品目录、Banner 轮播、营销活动（满减/券/秒杀）、满免邮活动、用户券与购物车；订单/售后/进销存/采购/收银样本与全局种子（社区/区划/账号/用户/站点）仅随 `market-admin init` 初始化导入，应用中心不展示
  - 导入后可指定商品上架状态（默认下架）；可指定目标会员手机号，用户券与购物车落到该会员名下，未指定时用户侧数据段禁止导入
  - 幂等键：社区按名称、账号按 username、用户按手机号、SKU 按社区内条码、分类按社区内名称；已存在即跳过，可安全重跑
  - 后端接口另有超管双闸（路由权限码 + handler 内实时超管校验，不认令牌快照），详见《06-接口设计/03-后台管理接口》「数据导入模块」

#### 应用中心与数据清理（2026-10-29）
- 数据清理（`/apps/data-import` 页内入口，仅超管）：与导入互为逆向操作，一键清空全部业务数据，用于把环境重置为空数据或重新导入演示数据做测试
  - 交互：预检（逐数据域展示将清理的行数、附件域附文件数，只读）→ 输入确认文案「确认清空全部业务数据」强确认 → 执行（返回删除记录/文件统计与失败明细）
  - 清理范围按逆依赖顺序分域：售后/退款 → 订单/POS → 支付流水（仅流水）→ 进销存 → 用户资产（购物车/持券）→ 营销 → 商品目录 → 附件 → C 端用户（含地址/会员关联，真实用户下次访问以 openid 重新注册）
  - 保留：支付配置、附件配置、站点设置、系统骨架（社区/管理员/角色/区划/渠道凭证）、单行系统配置（售后配置/应用偏好）、演示种子图片（`/uploads/seed/`，不在附件表、重导演示包自动复用）
  - 附件域记录硬删并删除上传的文件本体（本地 uploads 文件 / OSS 对象）；文件删除失败仅记明细不阻断；附件配置与种子图片不受影响
  - 安全：全部硬删（含软删行）；逐域独立事务，单域失败不阻断后续域；超管双闸与数据导入同模式，详见《06-接口设计/03-后台管理接口》「数据清理模块」

#### 附件上传
- 后台所有图片输入框（商品封面图、Banner 图片等）均提供「上传图片」按钮与缩略图预览（收在输入框内部右侧，宽度行为与普通输入框一致），同时保留手动输入 URL 能力
- 上传通道由附件配置自动分流：
  - 本地模式：multipart 上传至后端落盘，经 `/uploads/` 静态路径访问
  - OSS 模式：前端计算文件 MD5 → 获取预签名 URL → PUT 直传 OSS → confirm 确认；MD5 命中秒传时直接返回已有文件地址
- 图片地址存取规则：数据库只存相对路径，上传完成/手动输入后输入框回显完整 URL，提交时由后端剥离域名；页面展示时由后端按附件配置的访问域名拼回完整 URL（本地模式「自定义访问域名」选填：未配置时按 `/uploads/` 站内路径兜底、随访问域名解析；保存站点设置时仅当生效域名来自显式配置——站点域名或 `SITE_BASE_URL` 环境变量——才自动补写，按请求现推的域名不入库）
- 附件记录统一存于 attachment 表，用于秒传与追溯
