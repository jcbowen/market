### 4.4 后台管理端

#### 商品管理
- 商品分类管理（多级分类）
- 商品 CRUD
- 起订份数（`min_buy`，商品级，默认 1）：C 端下单逐行校验数量 ≥ `min_buy`；收银台代客下单（`source=2`）豁免，便于现场拆零/称重收款
- 商品上下架
- 多规格/SKU 管理（SKU 规格图片支持后台上传，C 端选中规格时展示对应图片）
- SKU 划线价（`original_price`，原价，0 表示不展示）：单规格与多规格 SKU 行均可录入，随商品创建/更新的 `sku_items` 全量提交（网关 `toProtoSkuItems` 透传至 product 服务）
- 商品划线价汇总：保存 SKU 时以最低价 SKU 的划线价回写商品 `min_original_price`，与列表起售价（`min_price`）取同一 SKU，C 端详情/列表按该汇总值展示划线价
- **商品条形码**（挂 SKU 级，单规格表单与多规格 SKU 列表均可录入，支持扫码枪直接录入）：纯数字 6-20 位宽松校验（不做 EAN 校验位强校验）；同社区内在售 SKU 间唯一，重复返回 10001 并提示占用商品名；商品软删后条码自动回收可复用；条码精确查询 `GET /admin/products/barcode/:code`（命中返回商品 + 具体 SKU）

#### 库存管理
- **商品入库**：采购入库、退货入库，记录入库时间、保质期、批次号
- **商品出库**：销售出库（关联订单）、报损出库（过期/损坏）
- **库存盘点**：定期/不定期盘点，记录盘点差异，生成盘点单
- **库存预警**：低库存预警（低于安全库存）、保质期临期预警
- **库存流水**：所有库存变动记录，可追溯查询
- **一键生成补货单**：根据库存预警自动生成补货建议

#### 保质期管理
- 入库时录入生产日期 + 保质天数，自动计算过期日期
- 支持手动录入过期日期
- 临期预警提醒（可配置提前天数）

#### 订单管理
- 订单列表（状态/订单号/收货人姓名电话/下单时间范围/**来源**筛选；状态口径与后端聚合一致：待发货=已支付∪备货中，售后=退款中∪已退款；来源列 + 经手人列，详情展示来源与经手人；**2026-10-24 筛选增强**——①「支付单号/渠道交易号」单框：粘贴支付宝账单「商家订单号」或「支付宝交易号」任一即可搜到对应订单（gateway 先经 payment 服务反查订单号，字段渠道无关，后续微信等新渠道零改动）；②「选择会员」：弹出会员选择器按会员过滤；③「选择商品」：弹出商品选择器按商品过滤（含全部规格）；④下单时间旁快捷按钮「今天/昨天/近7天/近30天」，与手选日期范围互斥联动；低频筛选（会员/商品/收货人/电话）折叠进「更多筛选」，已设置条件时按钮显示计数）
- 状态概览卡片（点击即筛选对应状态）
- 订单详情（含物流信息展示与按状态渲染的操作按钮）
- **售后记录区块**：逐条展示本单每次退款（退款单类型「整单退/部分退/金额退」标签、退款金额并标注含运费金额、退款商品明细「商品名(规格)×数量」，仅金额退显示「不退商品」、**订单本身无商品行（`order_item_count=0`，收银台直接收款单）显示「无商品明细（直接收款）」**、退款单状态标签、退款原因/退款时间），无售后记录时区块不渲染；**「无商品明细」按订单口径（`order_item_count`，proto 数字 0 会被省略，前端统一 `?? 0` 归一）判定，不看本退款行有无 `items`**——仅金额退在全额退完时同样升为整单退（type=1）且没有明细，误判会把普通单标成直接收款；与售后管理页同源数据；**行内审核（2026-10-23）**——待审核售后单在操作列直接提供「同意/拒绝」（逻辑与售后管理页一致：同意二次确认、拒绝原因必填），免关单跳转售后管理页
- **无商品单展示（2026-10-25）**：订单详情商品明细为空时（收银台直接收款单）展示「该订单无商品明细（直接收款）」空状态，不再渲染空白表格；订单导出商品明细列输出「直接收款（无商品）」。
- 订单列表/详情展示支付方式（pay_type：微信/支付宝/货到付款/现金）；**支付方式图标化（2026-10-25）**：以渠道品牌色图标展示（微信=绿色气泡/支付宝=蓝色/现金=橙色钞票/付款码=扫码/货到付款=钱包图标），**列表仅图标**（桌面悬浮/触屏点按经 tooltip 显示文字，2026-10-25 修订），详情弹窗图标+文字；后台与收银台订单查询共用 PayTypeLabel 组件，未接入渠道或待支付单仅显示文字
- 发货操作（仅配送单；物流公司/单号必填，写入独立字段）
- 自提核销（自提单已支付后直接「核销完成」，无需发货）
- 取消订单（取消原因必填，取消后逐行回补库存并回补订单占用的优惠券）：后台列表/详情的取消入口与服务端口径一致——待支付单（任意支付方式）+ 货到付款未发货单（2 已支付/3 备货中）；配送中及之后走退款流程；门店单后台路径不做额外限制（只读控制仅在 C 端）
- 批量发货（选中配送单共用同一物流信息）与批量核销；订单导出改为**后台异步 CSV（2026-10-24）**：点「导出 CSV」创建任务立即返回（沿用当前筛选条件，所见即所导；单次上限 10 万行，超限截断并提示缩小范围），生成完成后在**右上角下载中心**取文件。**下载中心**（布局右上角下载图标）：弹出面板展示近 3 天任务（文件名/条件摘要/状态「排队中·生成中·已完成·失败」/大小/行数/生成时间），文件生成后保留 **3 天**到期自动清理（文件+记录）；有已完成未下载的文件时图标显示数字角标；下载留痕（次数/下载人/时间）；记录可见性——普通管理员仅见自己创建的，超管见全部并可删除任意记录（删除时文件一并删除）；下载走网关鉴权接口流式下发，不走公开静态目录
- 退款审核处理（C 端申请单：同意/拒绝；退款中卡单支持「重试退款」；审批动作落 refund_logs 日志）。**卡单自动重试的边界（2026-10-24）**：调度器按节流指针轮转核查，累计 24 次仍未收敛的单停止自动重试并落 `action=give_up` 轨迹（展开行显示「停止自动重试（转人工）」），同时支付侧的退款流水也会因连续查单失败（上限 10 次）退出自动收敛批次——两侧预算各自独立，所以处置必须一次动作两侧都改。**两个卡单出口按「碰不碰钱」区分（2026-10-24 B2）**：「重试退款」再次向渠道发起出款（要求支付侧流水已判失败或不存在，否则会回「退款处理中，请勿重复提交」）；「恢复自动收敛」只把支付侧 `retry_count/escalated` 与订单侧 `retry_count/last_checked_at` 归零、让系统重新去核实渠道终态，全程不触渠道、不动钱，是「微信退款 1-3 个工作日才到账、但系统已放弃收敛」这类死角的唯一出路。两者都要求先人工核实渠道事实，恢复收敛还必填核实依据（落 `refund_logs.action=reset` 的 remark 与 `payment_notify_logs` 的 `kind=7/result=11` 留痕，并顺带销掉该退款单此前的转办待办）；不允许直接改状态。**审核语义（2026-10-23 确认）**：同意=按申请金额全额退回原支付流水，同意时不提供修改退款金额入口——保持「同意=全额退、拒绝=不退」的简单语义；商家希望少退时走「拒绝 + 订单详情『退款』按钮主动部分退（免审核按金额执行）」组合覆盖
- 代客退款（后台/收银台发起，**免审核**：创建即置退款中并调用渠道退款，成功后统一收尾）：三种方式——整单退、部分商品退（勾选商品行与数量）、仅金额退（不退商品、不回补库存），金额默认服务端按实付汇算、可调低，整单退按运费策略决定是否退还运费；**无商品明细单（直接收款）只保留整单退/仅金额退，整单退按剩余可退金额执行且不产生退款明细**；详见《订单与支付》4.2.2

#### 收银台（独立应用 /pos，代客下单，决策点⑥⑨）
- 入口：应用中心 → 收银台（独立登录页与布局壳，不套后台框架）；订单管理 → 收银台保留旧入口
- 选顾客：复用会员选择器（单选），可选「散客」（user_id=0）；选会员后自动带出其名下未使用券供代选
- 现场注册会员：会员选择器开启 `registerable` + `register-scene="pos"`，「新增会员」输入手机号（必填）与昵称（选填，缺省「会员+尾号4位」）即可注册；后端幂等——手机号已注册时复用既有会员并自动关联当前社区（提示「该手机号已是会员，已自动关联本社区」），新注册提示成功；注册成功后单选模式直接选中回传，`is_new` 供后续新用户活动扩展
- 选商品：按名称/拼音搜索在售商品，单规格点击即加入小票，多规格弹窗选规格；数量步进/删除行；**搜索三通道（2026-10-25）**——中文名包含匹配、拼音首字母匹配（如 `kl` 命中「可乐」）、拼音全拼匹配（如 `kele` 命中「可乐」），字母关键词三通道并行命中；另支持 A-Z 首字母栏按商品名首字拼音分组筛选（通讯录式）；**「仅看有货」开关**隐藏库存为 0 的商品（缺货卡片仍置灰不可购）；**扫码直达**——搜索框输入纯数字条形码（6-20 位）回车（扫码枪等价于键盘输入+回车）时优先走条码精确查询，命中且库存 > 0 直接加入小票并清空输入，未命中保留关键词回落名称搜索（接口 `GET /admin/products/barcode/:code`，权限 `order:create`）
- 配送方式：自提 / 配送 / 到店（到店仅收银台可用，即买即走）；配送单需收银员直填联系人、电话与地址（收银台无地址簿）
- 现金当场结清：收银台现金通道（pay_type=4，与货到付款 3 区分），支付单创建即成功并同步订单状态；**实付为 0（全额优惠）自动结清**
- **直接收款按钮统一（2026-10-25）**：「付款码收款/现金收款」按钮统一高度与字号（48px/16px）并各配图标（付款码=扫码/现金=钞票），消除此前主/次按钮样式差异过大造成的困惑；付款码渠道未配置时按钮按设计降级隐藏
- **直接收款可选会员（2026-10-25）**：直接收款 Tab 金额区上方加「会员栏」——默认「散客」标签 + 「选会员」按钮，复用会员选择器（单选、含现场注册）；选中后标签变会员名（可关闭回散客）+「更换会员」；选中的会员随建单写入 `user_id`（付款码/现金两路同口径），现金确认文案与小票快照均带会员信息；放弃扫码复用遗留单的载荷判定纳入 user_id（换会员后同金额不复用他人名下的遗留单）；收款成功后保留会员选择便于连续收款
- 优惠计算：优惠券（代选）+ 满减 + 满额免配送费均由服务端下单时计算，页面金额仅作参考
- 订单来源：固定 `source=2`（收银台），记录经手人 ID/姓名快照；与 C 端单统一存储，订单列表按来源筛选 + 收银台订单快捷视图（来源下拉选「收银台」）
- 订单查询（2026-10-25 修订）：列表按后端返回的 `item_count` 判断商品明细——无商品单（直接收款，`item_count=0`）不显示「引用」按钮，详情商品明细区展示「该订单无商品明细（直接收款）」空状态；有商品的单保留「引用到收银台」；支付方式列图标+文字展示（与后台同口径，共用 PayTypeLabel 组件）
- **散客单补绑会员（2026-10-25）**：散客收款后顾客要求计入会员（积分等权益）时，在**收款成功小票弹窗**与**订单查询详情弹窗**均可「绑定会员」补录（复用会员选择器）；口径——仅散客单（user_id=0）可绑，**绑定后不可换绑/解绑**，仅限已支付后状态（2-5）的单，订单须属当前社区；后端 `POST /admin/orders/:id/bind-user`（order:update 权限）经条件更新 `WHERE user_id=0` 防并发重复绑定；小票弹窗绑定后展示只读「已绑定会员：xxx」状态条，客户行实时更新
- **订单查询筛选与后台订单列表同口径（2026-10-25，后端 ListOrders 全量支持、前端零后端改动）**：主条件行（订单号前缀匹配 / 状态 / 来源）+「更多筛选」折叠区——账单号（支付单号/渠道交易号）、会员（复用 UserPicker 单选）、商品（选择器 300ms 防抖）、取货码、收货人、电话、下单时间（daterange + 今天/昨天/近7天/近30天快捷档，与手选互斥联动）、班次（支持「本班」一键填入）；已设条件以可关闭标签回显（折叠态显示，× 单独清除），一键重置回初始态；筛选变更统一回到第一页刷新，慢响应按请求序号防竞态；低频项折叠控制收银台屏幕密度

- **取货核销页 UI（2026-10-25 重设计）**：左右分栏布局——左侧核销面板（大圆形扫码图标 + 8 格取货码输入格 + 数字键盘，输满 8 位自动查询，支持扫码枪与全局键盘监听：数字录入/退格/回车查询/ESC 清空重扫）；右侧结果区四态——等待扫码空态 / 未找到（橙色提示+码格抖动）/ 找到订单（订单卡，可核销）/ 核销成功（大对勾反馈 +「继续核销下一单」，不再立即重置以便确认）；保留防爆破限流与权限校验

#### 收银台交接班（班次体系）

#### 用户管理
- 会员列表按**当前社区语境**（请求头 `X-Community-Id`）过滤会员-社区关联（`user_communities`），即"本社区会员"视图；超管通过顶栏切换社区查看不同社区，没有跨社区"全部会员"视图
- 列表支持昵称/手机号关键字搜索、正常/拉黑状态筛选，展示归属社区；**不再展示「履约」标记列**（履约身份已改由员工绑定会员表达，见下条）
- 会员现场注册（后台会员管理与收银台共用同一幂等注册接口 `POST /admin/users`）：手机号已注册（含其他社区老会员）不报错，复用既有会员并自动补写当前社区关联；响应 `is_new` 区分「新注册」与「复用」，注册来源由 `scene` 标记（`admin` 后台 / `pos` 收银台，非白名单值按 admin 处理）；C 端登录自动建号的会员按同口径补默认昵称（「会员+尾号4位」，无手机号为「微信用户」），且已有昵称不会被重复登录覆盖
- 拉黑/恢复：拉黑后该会员 C 端登录与已登录请求（含 refresh_token 静默续期）均被拦截
- 履约人员配置（B 履约工作台）：履约人员 = 在本社区有任职、账号绑定了会员（`admin_users.user_id`）、且账号未禁用的员工（2026-10-18 起）。入口为员工管理的「绑定会员/解绑会员」（`user_id=0` 为解绑，仅超管可改），绑定后在该员工全部任职社区获得履约身份，解绑/停用/取消任职立即失效；旧的 `user_communities.is_fulfiller` 列已废弃并在服务启动时 DropColumn，会员列表不再提供「设为履约/取消履约」操作。履约人员可在 C 端履约工作台送货上门与核销自提订单

#### 工作台（仪表盘首页）
- 登录后默认落地页（`dashboard:view`）：欢迎横幅、核心指标卡片、待办中心、近 7 日营收趋势、热销排行与常用快捷入口
- 待办中心：待支付/待发货/待收货订单、支付异常（2026-10-24 新增，取异常队列 `pending`，资金安全类需人工核实）、售后待审核、退款中、库存预警共 7 项，数字来自各业务统计口径；点击待办项直达对应列表页并携带状态筛选（`/orders?status=N`、`/refunds?status=N`、`/payment-anomalies`，取值受列表页白名单约束，非法值回落「全部」），列表页 `onActivated` 时重新应用 query（keep-alive 缓存下重复进入按最新参数刷新，不停留在首次筛选状态）

#### 数据统计
- 社区数据统计（`statistics:view`）：订单统计、销售统计、商品销量排行、营收报表，按当前社区口径
- 全平台统计（`statistics:view` + 仅超管，系统空间「数据统计」菜单组）：超管查看全平台汇总与各社区数据；统计接口经 `scope=all`（全平台聚合）/ `community_id=N`（指定社区，供社区排行）指定口径，普通管理员传参一律忽略（回落本社区，防越权）；客单价按「分」取整，规避浮点尾差

#### 门店管理（社区级菜单组）
- 门店设置（`community:config`）：社区管理员自助维护本社区运营资料，可改白名单——联系电话、负责人、自提点地址、配送费/起送金额/配送范围、营业时间、社区外配送开关；仅展示不可改——社区名称、所在地区、详细地址、经纬度、负责人电话、营业状态
- 员工管理（`admin:view`）：当前社区的任职员工（随顶栏社区切换变化）；添加员工时 username 已存在则复用账号追加任职，否则新建账号；编辑资料 + 本社区多角色任职（全量覆盖）；移除仅删本社区任职，账号与其他社区任职保留
- 角色管理（`role:view`）：管理**当前社区**的私有角色；内置社区管理员角色（`community_admin`）在此页只读（其权限由超管在「社区权限」页维护）；普通管理员可勾选的权限点不超出自身当前社区权限，防越权放大

#### 系统管理（独立系统空间）
- 入口在右上角用户下拉，不在左侧业务菜单展示；路由 `meta.space='system'`，**仅超管可进入**（系统级权限点不对社区分配，社区管理员只见业务菜单），非超管直连 URL 由守卫回落到业务首页
- 社区/自提点管理（`community:view`，超管）：经纬度支持新窗口打开高德官方坐标拾取器选点，复制坐标后粘贴一键解析回填；高德拾取页有反嵌套限制，不做 iframe 嵌套，不对接高德 API
- 社区权限（`community:view` + superOnly，仅超管）：按社区设置**权限上限**（载体为该社区内置 `community_admin` 角色的权限集），保存后运行时权限解析与其取交集，立即对社区全员生效；系统级权限点（`community:*`、`region:*`、`settings:*`）不进入可分配列表并自动剔除；收紧上限时提示受影响的本社区私有角色；内置角色缺失的存量社区在首次保存时自动创建
- 账号管理（`admin:view` + superOnly，仅超管）：只管账号本身——列表/新增/停用启用/重置密码/超管标记；社区任职不在此维护（由各社区员工管理页按社区视角操作）
- 社区角色（`role:view` + superOnly，仅超管）：跨社区角色**只读总览**——查看各社区有哪些角色、权限点、所属社区与任职人数，可按社区筛选；需要改权限时点「到该社区管理」切社区语境回到角色管理页维护；`community_id=0` 的历史遗留行标「遗留·全局」，仅可删除不可编辑
- 行政区划（`region:view`/`region:update`）：省/市/区县三级树形管理（关键词、层级、状态筛选，命中自动展开祖先链），全量约 3400 条带内存 + localStorage 7 天缓存；「行政区划更新」任务走异步任务：拉取上游（镜像源，兜底民政部官方接口）→ 展示新增/变更差异 → 确认覆盖入库，覆盖后自动清缓存；地址前缀与地址编辑的区划代码依赖此数据
- 全局 Banner 配置（超管专属，仅管理 community_id=0 的全平台通用 banner，适用社区锁定"全平台通用"；与社区业务端 Banner 管理复用同一组件，按访问语境区分；社区语境下全局 banner 只读）
- 站点设置（读 `settings:view`，写 `settings:update` + 仅超管；平台配置组首项）：平台级品牌与**部署域名的唯一来源**
  - 分区：部署域名 / 派生地址（只读）/ 品牌信息（站点名称、logo、favicon 各自独立字段）/ 页脚与备案 / 搜索优化
  - 页脚与备案：版权文字与 ICP 备案号合并为一个**富文本编辑器**（Quill 2，BSD-3 开源可商用）编辑，仅开放加粗/斜体/下划线/链接/清除格式；服务端保存时按白名单消毒（仅 a/b/strong/i/em/u/p/br/span 与合规 href，脚本/事件属性/危险协议一律剥除，外链统一新窗口打开，链接样式固定为继承页脚颜色、无下划线），消毒后 ≤2000 字符
  - `base_url` 只填 `scheme://host`（服务端归一并拒绝带路径参数者），派生出微信与支付宝异步通知地址、支付宝支付完成回跳地址，以及附件外链与 HTML 注入用的绝对地址
  - 生效优先级：站点设置 `base_url` > 环境变量 `SITE_BASE_URL`（兜底默认值，未配置时站点设置页回填该值）> 按当前请求现推；页面回显当前生效域名与其来源，内网/环回地址给出「回调不可达」告警
  - 品牌字段（站点名/logo/favicon/版权/备案号/SEO 描述与关键词）由网关在返回前端 HTML 入口时注入 `<title>`、favicon、description/keywords 与 `og:*`，浏览器与搜索引擎爬虫读到同一份内容；配置取网关内存快照（TTL + `version` 驱动失效），不逐请求查库
  - 后台左侧菜单底部、登录页与「关于系统」页脚展示版权与备案号（富文本 HTML）；站点名称用于品牌位（与社区门店名分层，二者不混用）
- 渠道管理（`settings:view`/`settings:update`，仅超管）：维护 mp/gzh/app/h5 四类客户端渠道的 AppID/AppSecret 与启用状态，是小程序登录凭证与微信支付 AppID 的唯一来源
- 支付配置（`settings:view`/`settings:update`）：渠道开关与顺序、微信/支付宝参数、商户证书上传；三个回调地址（微信/支付宝异步通知、支付宝回跳）改为**由站点设置的部署域名派生的只读值**，本页不再手填，前端提交的回调地址一律被忽略；读取配置时若库中回调地址与派生值不一致则自愈回写（仅在已显式配置域名时发生）
- 售后配置（`settings:view`/`settings:update`）：整单退时的运费退还策略（always 始终退 / never 不退 / user_decide 由用户选择），以及**已完成单售后窗口** `completed_refund_hours`（默认 168 小时=7 天，0=关闭已完成单自助申请入口），保存即时生效、无需重启；入口在系统空间「系统管理」菜单（仅超管）
- 附件配置（`settings:view`/`settings:update`）：存储模式（本地 / 阿里云 OSS，预留 COS），OSS 预签名 URL 直传 + MD5 秒传；本地附件迁移工具入口在此页（路由 hidden，不进菜单）

#### 权限与菜单渲染（与 RBAC 实现对齐，详见《权限与数据隔离》）
- 权限模型为**权限点级 RBAC**，不是固定三级角色：账号（`admin_users`，含 `is_super` 标记）与「社区任职」（`admin_communities`：管理员 × 社区 × 角色，可多社区多角色）分离，角色（`admin_roles`）按社区归属区分全局角色（`community_id=0`）与社区私有角色
- 权限点命名 `模块:动作`（如 `product:view`、`order:create`、`refund:update`、`community:config`），清单集中在 `src/admin/src/constants/permissions.ts` 按模块分组维护；`*` 为通配全量
- 前端路由守卫按 `meta.permission` 判定（无权限保留登录态跳 `/403`，权限为空才登出兜底），左侧菜单按权限点 + `superOnly` 过滤，页面内按钮再按 `hasPermission` 控制（如附件配置的 `settings:update`）
- 后端网关每条管理路由挂 `RequirePermission("xxx")` 中间件：非 `admin` 类型令牌直接拒绝；超管放行；其余按（管理员 × 当前社区）**实时**解析任职角色权限并集，再与该社区的权限上限取交集，命中所需权限点之一即通过
- 收银台独立应用（`/pos`）页面同样按 `order:create` 判定，未选定社区时先跳社区选择页

#### 附件上传
- 后台所有图片输入框（商品封面图、Banner 图片等）均提供「上传图片」按钮与缩略图预览（收在输入框内部右侧，宽度行为与普通输入框一致），同时保留手动输入 URL 能力
- 上传通道由附件配置自动分流：
  - 本地模式：multipart 上传至后端落盘，经 `/uploads/` 静态路径访问
  - OSS 模式：前端计算文件 MD5 → 获取预签名 URL → PUT 直传 OSS → confirm 确认；MD5 命中秒传时直接返回已有文件地址
- 图片地址存取规则：数据库只存相对路径，上传完成/手动输入后输入框回显完整 URL，提交时由后端剥离域名；页面展示时由后端按附件配置的访问域名拼回完整 URL（本地模式需在附件配置中填写「自定义访问域名」）
- 附件记录统一存于 attachment 表，用于秒传与追溯
