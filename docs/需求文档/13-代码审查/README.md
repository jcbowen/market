## 后续审查的归档约定

- 新一轮全栈审查完成后，报告与处置台账按 `01-审查报告-YYYYMMDD.md` / `02-处置台账-YYYYMMDD.md` 命名迁入本册，并在《11-开发计划》登记一条收口项指向本册。
- 归档时必须同步修订文档内**指向旧路径的引用**（历史项正文里的文件路径），保证不产生悬空引用。
- 台账中「未提交 git」之类的过程性标记，归档时应更新为最终状态（如「已提交」），避免按过期口径复盘。
- 审查中「证伪/不成立」的条目不允许随删除丢弃：它们与真缺陷同等重要，缺失会导致同一误报被反复评估（2026-10-28 轮的 `["*"]` 权限绕过、SQLite 幂等、秒杀资损三条均属此类）。
