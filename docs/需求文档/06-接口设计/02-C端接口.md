      "id": 1,

**刷新 token 响应（`POST /auth/refresh`）：** 结构与登录响应完全一致——除新 `access_token` 外**同时返回轮换后的新 `refresh_token`** 与 `user` 完整信息，前端应替换本地旧值。校验口径：仅 `type=user` 且用途为 refresh 的 token 可刷新（用 access token 换取返回 11005），token 无效/过期返回 11002，用户被拉黑返回 11008「系统错误，请联系工作人员」。

#### 履约工作台模块（B）

社区履约人员专用：送货上门 + 自提核销共用一个工作台。所有接口除登录外还要求
当前用户在其**实时归属社区**（users.community_id，非 token 快照）是履约人员
（user_communities.is_fulfiller=1），否则返回 `11005 您不是本社区履约人员`；
未选择社区时返回 `11005 请先选择社区`。

| 方法 | 路径 | 说明 | 认证 |
|------|------|------|------|
| GET | /api/v1/user/fulfillment-status | 查询当前用户履约人员身份（`{is_fulfiller, community_id}`，我的页工作台入口显隐依据） | 是 |
| GET | /api/v1/fulfillment/orders | 工作台查单（?order_type=1自提/2送货&status_group=0进行中/5已完成&pagination）；送货单只返回指派给当前用户的，自提单为本社区全部待核销/已核销 | 是 |
| POST | /api/v1/fulfillment/orders/:id/start-delivery | 开始配送（status 2/3 → 4，写 deliver_time）；仅订单指派人可操作，未指派/他人指派返回 `11005` | 是 |
| POST | /api/v1/fulfillment/orders/:id/complete-delivery | 送达完成（status 4 → 5，body: proof_images 为签收照片 URL 数组，**必填 1~N 张**，决策点②）；照片先经上传接口取得 URL | 是 |
| POST | /api/v1/fulfillment/orders/:id/verify-pickup | 核销自提订单（body: pickup_code 8 位取货码）；服务端校验码匹配 + 社区归属 + 状态，核销即完成（status=5），重复核销拒绝 | 是 |
| POST | /api/v1/upload/image | C 端图片上传（multipart 字段 file，12MB 上限；签收凭证等用途，`is_display=false` 不进入后台附件选择器），返回 `{attach_id, url, ...}` | 是 |

**核销与状态日志口径：** 履约人员操作在 order_status_logs 中记 `operator_type=staff, operator_id=<user_id>`；
后台兜底核销记 `operator_type=admin`。自提核销与后台兜底核销共用同一服务端校验（防跨社区、防重复）。
