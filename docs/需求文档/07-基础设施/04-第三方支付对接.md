
#### 微信支付

- 使用 wego 库 `payment/` 包
- 支付方式：JSAPI（微信小程序）、H5 支付（微信服务号）
- 支付流程：
  1. 前端调用 `POST /api/v1/payments` 传入 `order_id` 和 `channel="wechat"`，不传 openid
  2. 后端校验微信支付 V3 配置完整性，不完整时直接返回错误
  3. 网关从用户资料解析微信 openid：手机号登录用户的 openid 为 `phone_<手机号>` 占位值，视为不可用
  4. 创建独立支付单（`payment_no` 使用 `ZF` + UUID），有可用 openid 走 JSAPI 统一下单，否则走 H5 下单
  5. 返回调起参数给前端：小程序端用 `uni.requestPayment` 调起 JSAPI（`signType` 为 RSA），H5 端跳转 `h5_url`（uni-app 未封装浏览器支付）
  6. 用户支付完成后，微信回调 `POST /api/v1/payments/callback/wechat`
  7. 后端通过 wego 验签解密，仅处理 `TRANSACTION.SUCCESS` 通知，更新支付单和订单状态
- 幂等性：
  - 支付回调通过 `payment_no` 保证幂等处理
  - 退款通过 `refund_no` 唯一索引保证幂等，重复提交直接返回成功
- 多次支付：一笔订单在支付成功前可多次发起支付；同订单、同支付方式且金额一致时复用已有待支付单及其调起参数，不再新建（复用仅限微信/支付宝这类需第三方调起参数的渠道）；订单已有支付成功记录时拒绝创建。`GetPayment` 仅查询支付成功（status=2）记录，因此待支付单不会被幂等校验误拦
- 校验失败按 fail-closed 处理：幂等校验与待支付单复用查询若发生数据库异常（非 `ErrRecordNotFound`），直接拒绝创建并返回内部错误，不把故障当作"无支付记录"放行，否则会产生多笔可实际扣款的支付单；底层错误只写服务端日志，对客户端返回统一业务文案
- 多次退款：一笔支付单支持多笔部分退款，累计退款金额不超过支付单金额；支付单累计退完时才标记为"已退款"
- 配置展示：当 `wechat` 支付 V3 配置不完整时，C 端不展示微信支付选项
- 前端约束：仅支付真实完成才提示"支付成功"；用户取消、跳转 H5 支付页或渠道未开通时不提示成功，统一回到订单详情以便重新支付
- 上线前置：开启微信渠道前必须先完成 `11-开发计划.md` 中的回调兜底、待支付单生命周期、prepay 时效三项。原因为 wego 无 CloseOrder 接口，订单取消后其待支付单在微信侧约 2 小时内仍可被支付，而该回调会因状态机拒绝 `6→2` 而回滚，形成"钱已扣、系统无成功记录"的资金挂账风险

#### 支付宝支付

- 当前保持关闭状态，后台保存渠道配置时会自动过滤 alipay
- 保留模拟实现，配置仅保存；如需启用需接入支付宝官方 SDK
- 支付流程：与微信支付类似，回调地址为 `/api/v1/payments/callback/alipay`
- 验签：使用支付宝公钥验证回调签名

#### 支付配置管理（数据库化）

- 支付配置（微信支付 V3、支付宝、渠道开关 `enabled_channels`）存储于数据库 `pay_config` 表（单行，id=1），不再使用 config.yaml
- 后台「系统管理 → 支付配置」页面维护，对应接口：
  - `GET /api/v1/admin/settings/payment`：读取配置，同时返回根据当前访问域名自动生成的回调 URL 建议（`suggested_urls`），引导使用人配置到微信商户平台/支付宝开放平台；私钥不回传明文，仅返回 `*_cert_uploaded` 上传状态
  - `PUT /api/v1/admin/settings/payment`：保存配置，即时生效无需重启
  - `POST /api/v1/admin/settings/payment/cert`：multipart 上传证书文件（支持 `.pem/.key/.txt/.crt`，最大 64KB），文件内容直接存入数据库
- 热更新：payment 服务进程内缓存配置并以 `updated_at` 作版本号，支付链路调用时检测到版本变更才重建支付客户端；数据库查询异常时降级使用缓存，不阻断支付
- 微信回调地址：`{域名}/api/v1/payments/callback/wechat`；支付宝回调地址：`{域名}/api/v1/payments/callback/alipay`

#### 现金支付

- 线下收款/货到付款，创建支付单时直接标记为支付成功并同步订单状态
- 不复用待支付现金单：现金支付无需第三方调起参数，复用待支付记录会跳过"置为已支付并同步订单状态"的副作用，导致订单停留在待支付而前端已提示支付成功
- 不经过第三方支付网关
- 退款时仅记录退款流水，不调用第三方接口
