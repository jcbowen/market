### 7.4 YAML 配置模板

配置文件为 `bin/config.yaml`（本地/非 Docker 运行）、`bin/config.docker.yaml`（多容器 compose 部署）与 `bin/config.allinone.yaml`（一体化镜像内置模板，构建时拷为镜像内 `/app/config.yaml`），结构定义见 `src/backend/common/config/config.go`，加载入口 `internal/bootstrap`。一体化镜像部署的运行期配置修改不走模板挂载，统一编辑宿主机 `./data/runtime/config.yaml` 源配置（entrypoint 首启从内置模板生成，见部署文档 9.3.4a）。

**key 命名注意**：`web_server`、`db`、`redis` 三段由 jcbaseGo 结构体解析，字段没有 yaml tag，按"字段名全小写"匹配，必须写成 `enablessl`、`drivername`、`parsetime`、`singulartable` 等全小写形式（`port`、`db` 为字符串值）；`jwt`、`log`、`grpc`、`geoip` 及末尾各服务 `*_service` 段在项目自身结构体上声明了 yaml tag，正常使用下划线。

**敏感凭据一律不入库**：MySQL/Redis 密码与 JWT 密钥由环境变量 `MYSQL_PASSWORD` / `REDIS_PASSWORD` / `JWT_SECRET` 在启动时覆盖配置文件空占位（`common/config/env.go` 的 `ApplyEnvOverrides`），Docker 部署经根目录 `.env` 注入。同函数还接受非凭据项 `TRUSTED_PROXIES`（逗号分隔的可信代理网段）与 debugger 三项 `DEBUGGER_ENABLED` / `DEBUGGER_ALLOWED_IPS`（逗号分隔的调试页面访问白名单）/ `DEBUGGER_SERVICE_NAME`（`debug_logs` 的来源标识）：页面白名单只 gateway 用，开关与来源标识 gateway 与 payment/order 三个进程都读（compose 下多服务共用一份配置模板，来源标识必须按进程注入才能区分 `debug_logs.service_name`；一体化部署由 entrypoint 覆写配置副本，不需要该变量）。另有一个不经该函数的网关环境变量 `SITE_BASE_URL`（部署域名基址）：由 `gateway/main.go` 直接读取并注入品牌快照，作为后台「站点设置」未配置时的**兜底默认值**（站点设置页回填该值，保存后以站点设置的 `base_url` 为准），二者都为空则按当前请求域名现推（详见 `10-部署方案/03-生产环境部署.md`）。

### 7.4.1 payment_reconcile 取值口径（2026-10-21 新增）

- **三个布尔项声明为 `*bool` 而非 `bool + default:"true"`**：框架在读取配置后会对结构体再做一次默认值填充（jcbaseGo 的 `CheckAndSetDefault`），零值一律被回填为 `default` 标签值，普通布尔字段无法表达「显式 false」。用指针三态由 `common/config/reconcile.go` 的访问器统一解释：`nil`（未配置）走默认，非 nil 原样生效。这与 debugger 段 `max_records/retention_days/sample_rate` 用 `*int/*float64` 是同一约定，新增「0/false 有意义」的配置项必须沿用指针，不要写成带 `default` 标签的普通数值字段。
- 生效值：`ReconcileEnabled()` 与 `CancelGuardEnabled()` 未配置均为 `true`，`AutoRefundStuckEnabled()` 未配置为 `false`；后两者在 `Enabled=false` 时一律返回 `false`（总开关可一票回退到本轮改动前的行为：只靠渠道回调确认、关单只改本地状态）。配置为 `nil`（`c == nil`）时同样按上述默认返回，保证测试与缺配置场景不 panic。
- 读取方：`enabled`/`pending_max_minutes`/`interval_seconds`/`min_age_seconds`/`throttle_minutes`/`max_reconcile_count`/`batch_size`/`notify_log_retention_days` 由 payment 服务的对账调度器与 `ClosePayments` 使用；`cancel_guard` 由 order 服务的取消前置确认使用（`confirmPaidWithChannel`）。数值项再经 `ReconcileInt(v, fallback)` 防御非正值（配 0/负数等同未配）。
- 环境覆盖：本段暂无环境变量注入通道，须改配置文件本身；`bin/config.docker.yaml`、`bin/config.allinone.yaml` 已写出显式默认值，删除整段行为不变（回落同样的默认）。
- 阈值语义与调度机制详见 [07-04-第三方支付对接](04-第三方支付对接.md) 的《支付回调可靠性（对账补偿与人工处置）》小节。
