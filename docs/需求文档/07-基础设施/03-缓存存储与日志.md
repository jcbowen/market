当前实现采用同步 gRPC 调用处理订单、库存、通知等业务流程，未引入 Kafka。后续业务量级增长后可按需引入消息队列进行异步解耦。

### 7.6 缓存策略

#### Key 命名规范

格式：`market:{module}:{entity}:{identifier}`

| Key 模式 | 说明 | TTL |
|----------|------|-----|
| market:user:token:{token} | JWT token 黑名单（登出） | 与 token 有效期一致 |
| market:user:info:{user_id} | 用户信息缓存 | 30min |
| market:product:detail:{id} | 商品详情 | 30min |
| market:product:list:{community_id}:{category_id}:{hash} | 商品列表（hash 为查询参数摘要） | 5min |
| market:category:tree:{community_id} | 分类树 | 1h |
| market:cart:{user_id} | 购物车（Hash 结构，field=sku_id） | 7d |
| market:community:list | 社区列表 | 1h |
| market:community:nearby:{lng}:{lat} | 附近社区 | 10min |
| market:flash_sale:stock:{sku_id} | 秒杀库存（Redis 预扣） | 活动结束后清除 |
| market:sms:code:{phone} | 短信验证码 | 5min |
| market:sms:limit:{phone} | 短信发送频率限制 | 60s |
| market:coupon:available:{community_id} | 可领优惠券列表 | 10min |

#### 缓存更新策略

- **读模式**：Cache Aside（先查缓存，缓存未命中查 DB 并回写缓存）
- **写模式**：更新 DB 后删除缓存（Delete Cache），保证最终一致性
- **热点商品**：启动时预热商品详情到缓存
- **秒杀场景**：活动开始前将库存加载到 Redis，活动期间直接在 Redis 扣减

### 7.7 文件存储方案

- **默认存储**：本地文件系统，路径 `bin/static/uploads/`
- **目录结构**：`uploads/{YYYYMM}/{uuid}.{ext}`
- **访问 URL**：`https://domain.com/uploads/202607/abc123.jpg`
- **文件类型限制**：jpg、jpeg、png、gif、webp
- **文件大小限制**：单文件最大 10MB
- **OSS 扩展**：预留阿里云 OSS 接口，通过配置切换存储方式
- **图片处理**：一期不处理缩略图，前端通过 CSS 控制显示；二期可接入图片处理服务

### 7.8 日志规范

- **日志库**：zap（高性能结构化日志）
- **格式**：生产环境 JSON，开发环境 Console
- **级别**：debug / info / warn / error
- **切割**：按文件大小切割（100MB），保留最近 30 个备份，最长保留 7 天
- **文件命名**：`logs/{service_name}.log`
- **请求日志**：每个 HTTP/gRPC 请求记录 method、path、status、latency、client_ip、trace_id
- **业务日志**：通过 context 传递 `trace_id`，贯穿整个调用链路
- **敏感信息**：禁止记录密码、手机号全号（脱敏处理）
