**构建与 CI**：CI 按职责拆成两处（2026-10-26）：

- 日常检查在自建 Gitea：`.gitea/workflows/ci.yml`，push main / PR 触发，跑后端 vet/test/build、golangci 静态检查与前后端构建；
- 发版在 GitHub：`.github/workflows/ci.yml`，仅推送 `v*` tag 触发，交叉编译 6 平台产物、构建双架构镜像并发布 GitHub Release。

两处构建时都 drop `go.mod` 的本地 replace，从公共 Go proxy 拉取 jcbaseGo / wego / alipay-sdk-go-all 已发布 tag。Gitea 侧不使用 services 端口映射（宿主 3306 已被占用），改为同网络服务名访问 MySQL / Redis；服务就绪不用 docker healthcheck（runner 的 `service_ready_timeout` 到点即判失败），由 job 内 `wait_tcp` 轮询端口、预算 20 分钟，失败时自动打印服务容器的 docker 状态与日志；前端不用 `actions/setup-node`（其主路径硬编码从 github.com 下载、`mirror` 输入只作用于回退分支），改为 `curl -L` 从 npmmirror CDN 直下 Node tarball。
