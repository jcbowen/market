### 2.3 微服务拆分

| 服务 | 职责 |
|---|---|
| gateway | API 网关，统一鉴权、限流、路由转发、静态文件服务 |
| user-service | 用户注册/登录、微信/支付宝授权、地址管理、会员管理 |
| product-service | 商品分类、商品列表/详情、库存管理、保质期管理 |
| order-service | 订单创建、状态流转、退款 |
| cart-service | 购物车增删改查 |
| payment-service | 微信支付/支付宝支付对接、支付回调 |

### 2.3 调用链路

```
[小程序 / H5 / Android] → [gateway :18080] → gRPC → [各微服务]
                                ↓
                    [本地 YAML 配置 / 固定 gRPC 服务地址]
```

### 2.4 数据模型自动表迁移

各微服务启动时，通过 GORM 的 AutoMigrate 能力自动完成数据库表结构的创建与增量更新，无需手动执行 SQL。

**要求：**

- 每个服务独立管理自身数据模型（Model）定义。
- 服务启动入口统一调用 `AutoMigrate` 方法，注册该服务下所有模型。
- 支持模型字段新增、索引新增等增量变更（GORM 原生能力）。
- 不删除已有字段或数据，避免线上数据丢失。
- 数据库初始化顺序由 docker-compose 健康检查保证，服务启动时若数据库未就绪应重试连接。
- 版本控制中保留模型定义变更记录，便于追溯。

### 2.5 静态文件加载方案

Go 网关通过 Gin 路由加载静态文件：

- `/s/` → 用户端 H5（`bin/static/h5/`）
- `/b/` → 后台管理（`bin/static/admin/`）
- `/api/` → API 接口代理转发
- `/` → 自动 302 跳转到 `/s/`
