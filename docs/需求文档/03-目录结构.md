## 三、目录结构

```
market/                          # 项目根目录，同时作为项目级 GOPATH
├── bin/                         # 运行时目录（所有编译产物 & 配置 & 静态文件，整目录 .gitignore，仅配置模板入库）
│   ├── gateway                  # API 网关二进制（build.mjs 交叉编译后把与本机一致的一份复制到 bin/ 根目录）
│   ├── user-service             # 用户服务二进制
│   ├── product-service          # 商品服务二进制
│   ├── order-service            # 订单服务二进制
│   ├── cart-service             # 购物车服务二进制
│   ├── payment-service          # 支付服务二进制
│   ├── darwin/ linux/ windows/  # build.mjs 三平台交叉编译产物目录（darwin=arm64、linux=arm64、windows=amd64；
│   │                            #   CI release 作业另行直编 linux/darwin/windows × amd64/arm64 共 6 平台产物，不入 git）
│   ├── static/                  # 前端静态资源
│   │   ├── h5/                  # 用户端 H5 编译产物
│   │   └── admin/               # 后台管理编译产物
│   ├── attachment/              # 本地模式附件落盘目录（product 写入、gateway 经 /uploads 静态路由读取；不入 git）
│   ├── data/geoip/              # GeoLite2-City.mmdb（download-geoip.mjs 下载更新；不入 git）
│   ├── runtime/                 # gateway 运行时配置快照 config.yaml（compose 挂载，框架每次启动回写；不入 git）
│   ├── config.yaml              # 本地配置文件（YAML，入库）
│   ├── config.docker.yaml       # Docker 配置文件（YAML，入库）
│   ├── config.local.yaml        # 开发者本机配置（不入 git）
│   └── logs/                    # 运行日志
├── pkg/                         # GOPATH/pkg，go mod tidy 下载的第三方依赖缓存
│   └── mod/                     # Go Modules 缓存目录（已加入 .gitignore，不放项目源码）
├── src/                         # 整个项目的源码
│   ├── client/                  # uni-app 用户端源码
│   ├── admin/                   # 后台管理端源码（Vue3 + Naive UI）
│   └── backend/                 # Go 后端源码
│       ├── go.mod               # Go 模块定义（模块路径：github.com/jcbowen/market/src/backend，go 1.26.0）
│       ├── go.sum               # 依赖校验文件
│       ├── gateway/             # API 网关（路由、中间件、HTTP handler）
│       ├── services/            # 微服务
│       │   ├── user/

│       │   ├── order/
│       │   ├── cart/
│       │   └── payment/
│       ├── internal/            # 后端内部公共模块

│       │                        #   2026-10-15_pos_cash_pay_type.sql（收银台现金 pay_type 细分）

│       └── deploy/              # Dockerfile

│   ├── package.json             # test / test:api / test:e2e / test:fullflow / test:admin / test:client / report

├── build.mjs                    # 后端三平台交叉编译（产物 bin/<os>/，本机一份复制到 bin/ 根目录）

├── start-all.mjs                # 一键启动：依赖检查 → 前后端构建 → 镜像构建 → docker compose 启动 → 测试数据初始化
├── deploy.mjs                   # 发布构建：前端构建 + build.mjs 后端交叉编译 + Docker 镜像构建（--up 可直接启动）
├── deps-tools.mjs               # 构建脚本共用的依赖自愈工具（npm install / go mod tidy / pull 重试等）
├── download-geoip.mjs           # GeoLite2-City.mmdb 下载更新（配合 crontab，见 IP 定位服务文档）

└── README.md
```

**目录约定说明：**

- `bin/` 是唯一的运行时目录。Go 后端通过 `go build` 输出二进制到此，前端 H5 / 管理后台构建后输出到 `bin/static/`。开发期间启动后端时，以 `bin/` 为工作目录运行；Docker 镜像中 `/app` 目录的内容也来自 `bin/`。`attachment/`、`data/geoip/`、`runtime/` 为运行期产生/下载的本地目录，均不入 git。
- `pkg/` 仅用于存放 `go mod tidy` 自动下载的第三方依赖缓存（`pkg/mod/`），**不得存放项目自身源码**，且已加入 `.gitignore` 进行过滤。
- `src/backend/common/` 存放后端所有公共包，包括 Protobuf 定义、配置读取、JWT、错误码、响应封装等。
- `src/backend/migrations/` 存放手工迁移 SQL：表结构由 GORM AutoMigrate 自动维护，但存量数据修正（如 pay_type 细分、Banner 展示位迁移、幂等键调整）需要按文件名顺序在对应环境手工执行。
- `tests/` 是独立的 Node 工程（自带 package.json），不随前端/后端构建，运行方式见部署方案 9.2.6。
- `src/backend/go.mod` 中的模块路径为 `github.com/jcbowen/market/src/backend`，因此 `src/backend/common/proto/user` 的 import 路径为 `github.com/jcbowen/market/src/backend/common/proto/user`。
- Docker 镜像构建时，构建上下文只保留 `bin/` 与 `src/backend/deploy/`（Dockerfile），其余目录均通过 `.dockerignore` 过滤。
