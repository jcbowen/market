### 微信支付上线前置项（商户配置就绪后、渠道开启前必须完成）

支付配置已迁移至数据库 `pay_config` 表，默认 `enabled_channels=["cash"]` 未含 `wechat`；网关渠道 guard 通过 payment 服务返回的 `WechatPaymentReady` 判断，微信配置不完整或渠道未开启时会拦下所有微信建单请求。待支付单只可能由微信渠道产生，因此以下三项在微信渠道开启前触发概率为零，暂不编码，避免无法验证的实现：

17. [ ] 回调兜底，防止资金挂账：订单已终态时 `handlePaySuccess` 会因状态机拒绝 `6→2` 而整体回滚，网关回 `FAIL` 触发微信持续重试，形成"钱已扣、系统无成功记录"。需改为：支付单或订单已不处于可支付状态时，登记异常并调用 wego `Refund` 自动退款，同时返回 SUCCESS 停止重试。
18. [ ] 待支付单生命周期：`scheduler.go` 超时取消与 `CancelOrder` 均不触及支付单，需同步关闭该订单下 `status=1` 的待支付单。新增 `status=5 已关闭`，不复用 `3 支付失败`（后者语义为微信侧确认失败）。支付单 status 当前无 UI 消费方，改动面仅限模型注释与接口文档。
19. [ ] prepay 时效控制：复用待支付单前校验创建时间，超过约 110 分钟则关闭旧单重新下单。wego `payment` 只有 `JSAPIPay/H5Pay/QueryOrder/Refund`，**没有 CloseOrder**，微信侧 prepay 约 2 小时内仍可被支付，故本项只能做本地标记，与第 17 项回调兜底配合才构成完整防线。
