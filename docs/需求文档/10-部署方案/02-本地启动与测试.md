
#### 9.2.1 Docker 一键启动（默认）

项目根目录提供了 [start-all.mjs](file:///Users/bowen/projects/mine/market/start-all.mjs) 脚本，可完成依赖检查、前后端构建、镜像构建、服务启动与测试数据初始化：

```bash
# 常规启动（保留已有数据）
node start-all.mjs

# 清理 MySQL/Redis 数据后重新启动
node start-all.mjs --clean

# 跳过构建，直接使用已有镜像/二进制
node start-all.mjs --skip-build

# 构建镜像时不使用 Docker 缓存
node start-all.mjs --no-cache

# 依赖不全时只报告原因，不自动执行 go mod tidy / npm install
node start-all.mjs --no-auto-fix
```

默认启动不会移除 MySQL/Redis 容器（数据卷与运行状态均保留），业务服务容器由 `docker compose up -d` 依据镜像变化按需重建；只有 `--clean` 才会 `down -v` 彻底清理。

**依赖自愈**：构建脚本（`start-all.mjs`、`deploy.mjs`、`build.mjs`、`build-select.mjs`）共用 [deps-tools.mjs](file:///Users/bowen/projects/mine/market/deps-tools.mjs)，命令失败时会先抓取输出判定原因，再决定是自动补齐还是给出人工指引：

| 检出的问题 | 脚本行为 |
|---|---|
| `node_modules` 缺失、或 `npm ls` 报缺包 | 自动 `npm install` 后重试构建一次 |
| `missing go.sum entry`、`updates to go.mod needed` 等模块不一致 | 编译前预检自动 `go mod tidy` + `go mod download` 后重试 |
| Docker 基础镜像拉取失败 | 自动 `docker compose pull` 后重试构建一次 |
| GeoIP 定位库缺失（`bin/data/geoip/*.mmdb`） | 自动调用 `download-geoip.mjs` 下载；失败只告警，不阻断启动 |
| 残留容器引用已删除的 Docker 网络（Docker Desktop 重启后常见） | 自动 `docker compose down`（保留数据卷）后重试启动一次 |
| 服务端口被其他进程占用 | 不代为处理，报出占用排查命令与 `docker-compose.yml` 的端口修改位置 |
| `go.mod` 的 `replace` 指向的本地模块目录不存在 | 不代为处理，直接报出缺失模块与期望路径 |
| 网络受限（代理不可达、DNS 失败等） | 不重试写操作，打印 GOPROXY / npm registry / 镜像加速的建议 |
| 代码本身的编译或类型错误 | 原样输出错误并终止，不做任何依赖改动 |

`go mod tidy` 会改写 `src/backend/go.mod`、`go.sum`（例如补上 `// indirect` 依赖），属于预期副作用，改动后需随代码一起提交。指定 `--no-auto-fix` 时上述写操作全部跳过，只提示人工执行的命令。

启动成功后，可通过以下地址访问：

| 入口 | 地址 | 说明 |
|---|---|---|
| 管理后台 | http://localhost:18080/b/ | 默认管理员：admin / admin123 |
| C 端 H5 | http://localhost:18080/s/ | 任意合法手机号输入即可登录（免验证码免密码，自动建号），预置号 13800138000 |
| 健康检查 | http://localhost:18080/health | 返回 HTTP 200 表示网关就绪 |

#### 9.2.2 非 Docker 本地启动

如果不想使用 Docker，可以在宿主机直接运行后端二进制：

**前置条件**

- 已安装 Go 1.26+、Node.js 18+、npm 9+
- 本地已启动 MySQL 8.0+ 与 Redis 7+
- 已根据本地环境修改 [bin/config.yaml](file:///Users/bowen/projects/mine/market/bin/config.yaml) 中的 `db`、`redis` 配置

**启动步骤**

```bash
# 1. 构建后端产物
#    ./build.mjs 交叉编译 Windows/macOS/Linux 三平台二进制，并把与本机一致的一份
#    复制到 bin/ 根目录；只构建当前需要时可 cd src/backend && go build -o ../../bin/gateway ./gateway/
#    前端产物：cd src/admin && npm run build；cd src/client && npm run build:h5
#
# 2. 启动所有服务（顺序无强制要求，网关可最后启动）
#    服务启动时各自执行 GORM AutoMigrate 建表，首次启动会多花几秒
#    注意：表结构全部由 AutoMigrate 生成，init.dev.sql 仅用于导入测试数据，
#         只能在服务启动、表已建好之后执行
#
#    CONFIG_FILE=bin/config.yaml ./bin/user-service &
#    CONFIG_FILE=bin/config.yaml ./bin/product-service &
#    CONFIG_FILE=bin/config.yaml ./bin/order-service &
#    CONFIG_FILE=bin/config.yaml ./bin/cart-service &
#    CONFIG_FILE=bin/config.yaml ./bin/payment-service &
#    CONFIG_FILE=bin/config.yaml ./bin/gateway &
#
# 3. 导入测试数据（可选，仅首次需要示例数据时执行）
#    deploy/init.dev.sql 只含 INSERT（管理员、测试用户与地址、社区、分类、商品、商品图集、SKU），
#    仅限开发环境使用，含弱口令账号，禁止导入生产库
mysql -h localhost -u root -pmarket123 market < deploy/init.dev.sql

# 4. 停止所有服务
#    手动 kill 对应后台进程
```

启动成功后访问地址与 Docker 方案一致。

非 Docker 方式下日志随各进程标准输出；如需集中查看日志与测试数据自动初始化，建议使用 9.2.1 的 `node start-all.mjs`（Docker）方案。

#### 9.2.3 Docker 连接外部 MySQL/Redis

默认 [docker-compose.yml](file:///Users/bowen/projects/mine/market/docker-compose.yml) 会启动内置的 MySQL 与 Redis。如需使用外部数据库：

1. 修改 [bin/config.docker.yaml](file:///Users/bowen/projects/mine/market/bin/config.docker.yaml) 中的 `db.host`、`db.password`、`redis.host`、`redis.password` 为外部实例地址与密码。
2. 使用外部数据库专用的 Compose 文件启动：

```bash
docker compose -f docker-compose.external-db.yml up -d
```

该文件不包含 MySQL/Redis 容器，仅启动 gateway 与各微服务。停止命令：

```bash
docker compose -f docker-compose.external-db.yml down
```

#### 9.2.4 单独构建与重启

如果只需要修改某一部分，可以单独构建：

```bash
# 构建管理端
cd src/admin && npm run build

# 构建 C 端 H5（会自动执行 build-frame.js 处理 iframe 嵌套）
cd src/client && npm run build:h5

# 构建后端二进制（Windows/macOS/Linux 三平台交叉编译，产物在 bin/<os>/）
# build.mjs 结束后会把与本机一致的一份复制到 bin/ 根目录，
# 因此同一份产物既可用于 Docker 镜像构建，也可直接用于非 Docker 本地运行
node build.mjs

# 重新构建并启动 Docker 服务
docker compose build
docker compose up -d
```

修改前端静态资源后，[docker-compose.yml](file:///Users/bowen/projects/mine/market/docker-compose.yml) 已把 `./bin/static/admin`、`./bin/static/h5` 只读挂载进 gateway 容器，新产物一般刷新浏览器即可看到。

需要注意前端构建脚本会先 `rm -rf` 产物目录再重新生成，仍在运行的容器绑定的是被删除的旧目录 inode，挂载点会因此变空（表现是 `/s/` 或 `/b/` 返回 404）。出现这种情况执行 `docker compose restart gateway` 让容器重新解析挂载即可；`node start-all.mjs` 与 `node deploy.mjs --up` 在重新构建前端后已自动执行这一步，单独跑 `npm run build` / `npm run build:h5` 时才需要手动重启。

#### 9.2.6 自动化测试

项目自带基于 Playwright（Node + TypeScript）的全量自动化测试，位于根目录 `tests/`（独立 npm 工程），覆盖后端 API（C 端 + 管理端）与管理端/C 端浏览器 E2E。配置见 `tests/playwright.config.ts`：`baseURL` 默认 `http://localhost:18080`（可用 `TEST_BASE_URL` 覆盖），`workers=1` 顺序执行规避数据竞争，globalSetup 启动时探测 `/health`（服务未启动直接终止并提示）。

```bash
# 前置：先启动整套服务（node start-all.mjs），测试只检测环境不自动拉起
cd tests
npm install && npx playwright install chromium   # 首次
npm test                                          # 全量（API + E2E）
npm run test:api                                  # 仅后端接口（api/）
npm run test:e2e                                  # 仅浏览器 E2E（e2e/）
npm run test:admin                                # 仅管理端 E2E（e2e/admin/）
npm run test:client                               # 仅 C 端 H5 E2E（e2e/client/）
npm run test:fullflow                             # 仅全流程串联（e2e/fullflow.spec.ts）
npm run report                                    # 查看 HTML 报告（等价 npx playwright show-report）
```

#### 9.2.8 接口变更与测试同步约定

- **改接口必须同步改测试**：新增或修改接口路径、请求字段、响应口径、状态机流转时，同一轮须补/改 `tests/api/` 用例并本地跑通。当前 CI 不执行 Playwright，这道门禁由人工在提交前跑 `npm run test:api`（可只跑相关 spec）承担；后续若把 Playwright 纳入 CI，须同时保证服务已启动且测试数据可重复生成。
- **服务层行为变更会打破既有断言**：例如「到店单收款即同事务终态化为已完成」使代客退款（仅允许状态 2/3/4）无法作用于到店单，此类回归至少要复跑 `14-pos`、`44-pos-shift-snapshot`、`49-order-status-transition`、`30-cod-cancel`。
- **造数惯例**：名称统一 `AUTO-TEST` 前缀、手机号自增，`afterAll` 逆序清理；进销存单据（供应商、采购单）无删除接口且供应商受引用保护，按「只增不删」留档，单号/名称带本轮 tag 便于人工识别。软删商品（`products.status=2`）的 SKU 仍会出现在进销存报表中（已知未修缺陷），清理测试数据时不能只看商品列表。
- **下单限流是真实网关行为**：`POST /api/v1/orders` 挂有按用户 ID 的令牌桶（容量 5、每 12.5 秒回补 1，超限返回 `10005` 并带 `Retry-After: 12`），另有 5 秒「重复下单指纹」判重窗口（同用户+社区+配送方式+券+商品列表含数量视为重复）。批量下单的用例须等待令牌回补重试或错开商品数量，勿把限流误判成业务失败。
- **运行环境**：`tests/` 为独立 npm 工程，需 Node 20（`nvm use 20`）；首次执行 `npm install && npx playwright install chromium`；配置为 `workers=1` 顺序执行、`retries=2`、失败保留 trace，`baseURL` 默认 `http://localhost:18080`（`TEST_BASE_URL` 可覆盖）。
