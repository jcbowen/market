## 五、数据库设计

### 5.1 设计规范

- 所有表使用 InnoDB 引擎，字符集 utf8mb4，排序规则 utf8mb4_unicode_ci
- 主键统一使用 `id BIGINT UNSIGNED AUTO_INCREMENT`
- 时间字段统一：`created_at`、`updated_at`、`deleted_at`（GORM 软删除）
- 金额字段统一使用 `DECIMAL(10,2)`
- 状态字段使用 `TINYINT`，0 表示禁用/删除，1 表示正常
- 索引命名：普通索引 `idx_表名_字段名`；单列唯一约束使用 GORM `unique` 标签，自动生成 `uni_表名_字段名`；复合唯一索引使用命名 `uniqueIndex`（如 `uk_user_sku`）。注意：单列唯一不得使用 `uniqueIndex` 标签，GORM 增量迁移时会误判并尝试删除不存在的约束导致迁移失败
- 迁移策略：所有表统一走 GORM AutoMigrate（服务启动时执行），禁止手写 CREATE TABLE / ALTER TABLE 等幂等 DDL 迁移函数；每个服务新增模型后必须加入该服务 main.go 的 autoMigrate 列表，不允许存在不参与迁移的模型
- 默认值写法：DECIMAL 字段的 tag 默认值必须写 `default:0.00`（与 MySQL 存储值一致），写 `default:0` 会导致每次启动误发 ALTER TABLE
- 模型对齐：模型 tag 必须与 DB 实际列定义逐项对齐（type、not null、default、comment），AutoMigrate 对已有表做全量比对，不一致即触发 AlterColumn
- 幂等验收：同一份代码连续启动两次服务，第二次启动的迁移日志中不允许出现任何 DDL 语句
- 数据隔离：涉及社区的表均含 `community_id` 字段，联合索引隔离
