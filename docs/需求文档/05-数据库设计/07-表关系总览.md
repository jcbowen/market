说明：

- `stock_checks`（盘点单）与 `stock_check_items`（盘点明细）：模型 `StockCheck.TableName()` 为复数 `stock_checks`，明细表按 `check_id` 关联。
- `stock_op_logs` 幂等键为 `(order_id, sku_id, op_type, biz_no)` 复合唯一：`biz_no` 取退款单号、`cancel:{orderID}`（超时取消）、`comp:{orderID}:{skuID}`（下单补偿），同一业务号重复请求只生效一次，同一订单同一 SKU 的多笔部分退款各自独立幂等。释放库存时由 order 服务把 `refunds.refund_no` 作为 `biz_no` 传入。存量库需手动执行 `src/backend/migrations/2026-10-16_stock_release_biz_no.sql` 删除旧三列索引 `uk_stock_op_order_sku`（详见 03 商品服务表结构）。
- `refunds` 与 `orders`：退款类型 `type` 为 1整单退 / 2部分退 / 3仅金额退；`type=3` 时不写 `refund_items` 明细行、退款成功后不回补库存（仅退金额），累计成功退款（含运费）达到实付后本笔退款单类型升级为 1 整单退、订单置 8 已退款。退款单与支付侧通过 `refund_no` / `payment_no` 双向关联（`refund_payments.refund_no` 唯一，保证退款请求幂等）。
- 行政区划为口径引用而非物理外键：`user_addresses.province_code / city_code / district_code`、`communities.province_code / city_code / district_code` 指向 `regions.code`（`communities` 另存省市区名称快照）。
- 单行配置表 `refund_config`（固定 id=1）、`pay_config`、`attachment_config`（固定 id=1）不参与上述关联。
