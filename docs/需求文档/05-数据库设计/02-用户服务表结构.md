**user_communities - 会员-社区关联表**

多社区会员模型：会员可在多个社区出现，满足以下任一业务行为即建立关联（幂等）：
在该社区添加过收货地址、在该社区下过单、后台在该社区添加注册的会员。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | 是 | 主键 |
| user_id | BIGINT | 是 | 用户 ID |
| community_id | BIGINT | 是 | 社区 ID |
| source | VARCHAR(20) | 否 | 关联来源：address 收货地址 / order 下单 / admin 后台添加 / backfill 存量回填 |
| is_fulfiller | TINYINT(1) | 是（默认0） | 是否履约人员（B 履约工作台）：该用户在该社区可送货上门 + 自提核销；后台会员管理设置，C 端工作台入口与履约接口鉴权依据 |
| created_at | DATETIME | 是 | 创建时间 |

索引：`uk_user_community(user_id, community_id)`

**admin_users - 管理员表（账号层）**

多社区任职模型下仅承载账号身份属性；社区内的角色与权限通过 admin_communities 任职表表达。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT UNSIGNED | 是 | 主键 |
| username | VARCHAR(50) | 是 | 用户名 |
| password | VARCHAR(255) | 是 | bcrypt 加密 |
| real_name | VARCHAR(50) | 否 | 真实姓名 |
| phone | VARCHAR(20) | 否 | 手机号 |
| is_super | TINYINT | 是 | 是否超级管理员（不受社区与角色约束），默认0 |
| status | TINYINT | 是 | 1正常 0禁用，默认1 |
| last_login_at | DATETIME | 否 | 最后登录时间 |
| last_login_ip | VARCHAR(50) | 否 | 最后登录 IP |
| created_at | DATETIME | 是 | |
| updated_at | DATETIME | 是 | |
| deleted_at | DATETIME | 否 | |

索引：`uni_admin_users_username(username)`
说明：历史遗留的 `role_id` / `community_id` 列在 DB 中保留，代码已废弃不再读写。

**admin_communities - 管理员任职表（账号 × 社区 × 角色）**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | 是 | 主键 |
| admin_id | BIGINT | 是 | 管理员 ID |
| community_id | BIGINT | 是 | 任职社区 ID |
| role_id | BIGINT | 是 | 担任角色 ID（须为该社区的角色） |
| created_at | DATETIME | 是 | 创建时间 |

说明：一个账号可在多个社区任职、同一社区可兼任多角色；内置 community_admin 角色每社区仅一人（指定新管理员时自动替换原任职者）。
