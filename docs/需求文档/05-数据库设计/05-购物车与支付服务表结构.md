#### 5.2.5 payment-service（支付服务）

**payments - 支付记录表**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | 是 | 主键 |
| payment_no | VARCHAR(50) | 是 | 支付单号，使用 UUID 生成 |
| order_id | BIGINT | 是 | 订单 ID |
| user_id | BIGINT | 是 | 用户 ID |
| pay_type | TINYINT | 是 | 1微信支付 2支付宝支付 3货到付款 4现金（收银台，含 0 元单；后续付款码渠道预留 5/6） |
| amount | DECIMAL(10,2) | 是 | 支付金额 |
| status | TINYINT | 是 | 1待支付 2支付成功 3支付失败 4已退款 5已关闭 |
| transaction_id | VARCHAR(100) | 否 | 第三方交易号 |
| pay_params | TEXT | 否 | 第三方支付调起参数 JSON |
| pay_time | DATETIME | 否 | 支付时间 |
| created_at | DATETIME | 是 | |
| updated_at | DATETIME | 是 | |

索引：`uni_payments_payment_no(payment_no)`、`idx_payments_order_id(order_id)`、`idx_payments_user_id(user_id)`

> `status=5 已关闭`：订单进入取消/退款等终态后由订单服务 `ClosePayments` 按订单批量关单，迟到的第三方支付成功回调遇到已关闭支付单不再落账（金额强校验 + 条件更新幂等，详见 gRPC 接口设计文档「支付回调与关单语义」）。

**pay_config - 支付配置表（单行存储，id 固定为 1）**

支付配置（微信支付/支付宝/渠道开关）由 config.yaml 迁移至本表，通过后台「系统管理 → 支付配置」维护，保存后即时生效（payment 服务按 updated_at 版本检测热更新，无需重启）。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键，固定为 1 |
| enabled_channels | VARCHAR(100) | 启用的支付渠道 JSON 数组，可选值 wechat/alipay/cash，决定 C 端展示与顺序 |
| wechat_channels | VARCHAR(255) | 微信支付适用客户端渠道 JSON 数组（mp/gzh/app/h5），空=全部客户端渠道可用（存量兼容口径） |
| alipay_channels | VARCHAR(255) | 支付宝适用客户端渠道 JSON 数组（mp/gzh/app/h5），空=全部客户端渠道可用 |
| wechat_app_id | VARCHAR(64) | 微信支付默认 AppID（H5 下单与回调客户端兜底；小程序等按端 AppID 由渠道管理配置并在下单时传入覆盖） |
| wechat_app_secret | VARCHAR(128) | 微信支付默认 AppSecret |
| wechat_mch_id | VARCHAR(32) | 微信支付商户号 |
| wechat_api_v3_key | VARCHAR(64) | 微信支付 V3 API 密钥 |
| wechat_cert_serial_no | VARCHAR(64) | 商户证书序列号 |
| wechat_private_key | TEXT | 商户私钥 PEM 内容（后台直接上传 apiclient_key.pem 文件，内容存库，不回传明文） |
| wechat_notify_url | VARCHAR(255) | 微信支付结果通知 URL |
| alipay_app_id | VARCHAR(64) | 支付宝 AppID |
| alipay_private_key | TEXT | 支付宝应用私钥内容 |
| alipay_public_key | TEXT | 支付宝公钥内容 |
| alipay_notify_url | VARCHAR(255) | 支付宝异步通知 URL |
| alipay_return_url | VARCHAR(255) | 支付宝支付完成回跳 URL |
| created_at | DATETIME | |
| updated_at | DATETIME | 更新时间，兼作配置版本号 |

说明：
- 首次启动（payment 服务 AutoMigrate 后）表为空时自动写入一条默认记录（仅启用 cash 渠道）
- 后台保存配置接口会将 alipay 从渠道列表中过滤，支付宝支付保持关闭
- 回调 URL 由后台配置页面根据当前访问域名自动生成引导，微信回调地址为 `/api/v1/payments/callback/wechat`，支付宝为 `/api/v1/payments/callback/alipay`
- 各客户端渠道的访问凭证（AppID/AppSecret）不在本表，统一由 user 服务 `client_channels` 表管理（见「用户服务表结构」），微信 JSAPI 下单时由网关按客户端渠道解析 AppID/openid 后传入


**client_channels - 客户端渠道表（user 服务）**

后台「系统管理 → 渠道管理」维护各客户端访问凭证、启用开关与排序；小程序登录（Code2Session）、未来的公众号 OAuth、按端支付下单均取用此处配置，保存后即时生效（登录/下单链路每次现取，无缓存）。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| code | VARCHAR(32) | 渠道标识，唯一索引：mp 微信小程序 / gzh 微信公众号 / app 开放平台App / h5 浏览器H5 |
| name | VARCHAR(64) | 显示名称 |
| app_id | VARCHAR(64) | 渠道 AppID |
| app_secret | VARCHAR(128) | 渠道 AppSecret |
| enabled | TINYINT(1) | 是否启用（未启用时该端登录/支付能力不可用） |
| sort | INT | 排序值 |
| created_at / updated_at | DATETIME | |

说明：
- 首次启动（user 服务 AutoMigrate 后）表为空时写入 4 条内置渠道：mp/gzh/app 默认停用待配置，h5 无需凭证默认启用
- h5 渠道凭证完整性恒为 true（无需 AppID/AppSecret）


**user_channel_identities - 用户渠道身份表（user 服务）**

按客户端渠道存储用户的微信 openid/unionid（同一微信用户在不同 appid 下 openid 不同），唯一索引 `uk_user_channel(user_id, channel_code)`。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| user_id | BIGINT | 用户 ID |
| channel_code | VARCHAR(32) | 客户端渠道 code |
| openid | VARCHAR(64) | 该渠道下的微信 openid |
| unionid | VARCHAR(64) | 微信开放平台 unionid |
| created_at / updated_at | DATETIME | |

说明：
- 存量 `users.openid` 单列视为 mp 渠道口径，查询时回落读取（排除 phone_ 占位），不做数据迁移
- 小程序登录成功后幂等 upsert 本表
