**payment_notify_logs - 支付通知与对账流水表（2026-10-21 新增）**

记录「渠道通知 / 主动回查 / 人工同步」三类动作的完整轨迹，承担两个职责：一是**取证**（验签或解密失败的原始报文必须留痕，否则事后无法区分「渠道发过但被拒」与「渠道根本没发」）；二是**出口**（把散落在 stderr 的 `[CRITICAL]` 挂账、金额不符、放弃对账变成可查询、可销账的后台队列）。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT | 是 | 主键 |
| kind | TINYINT | 是 | 类别：1渠道回调 2对账补同步 3挂账检出 4渠道关单 5后台手动同步 6放弃对账 |
| result | TINYINT | 是 | 结果：1确认成功 2幂等忽略 3验签或解密失败 4金额不符 5处理异常 6渠道未支付 7渠道无此交易 8关单结果 9资金挂账 |
| channel | TINYINT | 是 | 1微信 2支付宝 |
| payment_no | VARCHAR(50) | 是 | 支付单号，验签失败时可能解析不出，为空串 |
| order_id | BIGINT | 是 | 订单 ID，同上可为 0 |
| order_no | VARCHAR(50) | 是 | 订单号快照，`order_id` 解析不出时后台仍可定位 |
| community_id | BIGINT | 是 | 归属社区，取自支付单快照；0=未知（验签失败等连支付单都解析不出的流水），仅超管全量队列可见 |
| handled | TINYINT | 是 | 销账标记：0待处理（进异常页） 1已处理/无需处理。由 `NeedsHandling(kind, result)` 判定落库值，与接口入参的筛选选择器口径不同（见后台管理接口文档） |
| error_msg | VARCHAR(500) | 否 | 结果摘要或失败原因 |
| remark | VARCHAR(255) | 否 | 人工销账备注（核实依据） |
| raw_body | TEXT | 否 | 原始通知报文，**仅失败与挂账场景存储**；成功回调不落此列（同一事实已在 payments 表） |
| headers | TEXT | 否 | 关键请求头 JSON，签名与证书序列号**入库前掩码** |
| created_at | DATETIME | 是 | |
| updated_at | DATETIME | 是 | |

索引：`idx_notify_kind_result_created(kind, result, created_at)`、`idx_notify_handled_created(kind, handled, created_at)`、`idx_notify_community_handled(community_id, handled, created_at)`、`idx_payment_notify_logs_payment_no(payment_no)`、`idx_payment_notify_logs_order_id(order_id)`（后两个为 GORM 无名索引默认命名）

说明：
- `handled=0`（待处理）的判定：金额不符与资金挂账不分来源都进队列（钱可能少收/多收，或已收而订单已取消）；此外 `kind=3 挂账检出`、`kind=6 放弃对账` 必进，`kind=1 渠道回调` 仅在验签失败或处理异常时进。成功、幂等忽略、渠道明确未支付属正常轨迹，落库备查但不打扰人工。
- `raw_body`/`headers` 只在具备 `payment:raw:view` 权限点时由网关回填下发（该权限点刻意不授予社区管理员），列表页默认只回摘要与 `has_raw` 标志。
- 过期清理由 payment 对账调度器按 `business.payment_reconcile.notify_log_retention_days`（默认 30 天）执行。
