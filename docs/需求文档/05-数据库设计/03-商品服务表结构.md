**stock_op_logs - 库存操作幂等日志表**

说明：不存完整访问 URL（原 url 列已移除），响应 URL 一律按附件配置动态拼接，域名变更无需迁移记录。

本地模式对象路径规则：`images/{Ymd}/{dd}/mkt{HHmmss}{6位随机}.{ext}`，落盘 `<部署目录>/attachment/` 下，经网关 `/uploads/` 静态路径访问。

本地模式与 OSS 直传的差异：本地上传的后端持有文件完整内容，`md5` 与图片尺寸（width/height）一律由后端从文件内容计算（png/jpeg/gif 走标准库，bmp/webp 由 golang.org/x/image 解码，ico 手写头解析，heic 暂无纯 Go 轻量解码器探测为 0）；OSS 直传后端不接触文件内容，md5 与尺寸由客户端随 presign 请求传入。

**图片 URL 存储与回显规则**：业务表图片字段（如 `products.cover_image`、`product_images.url`、`banners.image_url`、`product_skus.image` 规格图片）统一只存附件相对路径（remote_path 形态，如 `images/20261011/11/mktxxx.jpg`，不含 `/uploads/` 前缀与域名）。写入时由 product 服务 `ToSourcePath` 剥离域名归一化（SKU 图片在 CreateProduct/UpdateProduct 内随 `sku_items[].image` 一并归一化）；查询时由 `ToMediaURL` 按附件配置拼接完整访问 URL（local：`<visit_domain>/uploads/<path>`，oss：`<CDN 或 bucket 域名>/<path>`，SKU 图片经 GetProduct/ListSkus/GetSkuById 出库时拼接），存量完整 URL 兼容显示并在下次保存时自动归一化。

| status | VARCHAR(24) | 状态：pending 待迁移 / migrating 迁移中 / migrated 已迁移待验证 / verified 验证成功 / failed 迁移失败 / verify_failed 验证失败 / local_deleted 本地已删除 / orphan 孤儿文件（本地存在但附件表无记录，不参与迁移）；默认 pending |
| error_msg | VARCHAR(512) | 最近一次迁移/验证失败原因（超长截断） |
| migrated_at | DATETIME NULL | 迁移成功时间 |
| verified_at | DATETIME NULL | 验证成功时间 |
| local_deleted_at | DATETIME NULL | 本地文件删除时间 |
| created_at | DATETIME | |
| updated_at | DATETIME | |

索引：`path` 唯一索引（模型列级 `unique` tag 声明，生成 `uni_attachment_migrate_item_path`；勿改用 `uniqueIndex` tag——gorm v1.31 对「列存在 UNI 索引但字段无 unique tag」会每次 AutoMigrate 尝试 DROP `uni_` 前缀约束，MySQL 无此外键导致启动失败）、`idx_migrate_status(status)`（模型显式命名的单列索引）

说明：条目与附件记录按 `path` 同口径匹配（模型无 attachment_id 列），扫描时与 `attachment` 表全量比对。

扫描与生命周期规则：
- 扫描（scan）遍历本地附件目录并与 `attachment` 表全量匹配：两方都有 → pending（已存在条目仅刷新 size 等信息并保留状态进度）；仅本地有 → orphan；仅表有（本地文件缺失）→ 计入缺失数提示，不建条目。
- 迁移成功后自动验证（OSS `List(prefix=path)` 精确匹配对象名并比对大小），验证通过置 verified；失败置 verify_failed 可重试。
- 本地文件删除仅允许对 verified 条目执行（单个或批量），删除后置 local_deleted；再次扫描时该类条目不再清理，其余在本地与表中均已消失的条目自动清除。
