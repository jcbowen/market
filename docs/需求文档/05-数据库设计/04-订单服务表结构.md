**status 值域补充说明**

- `9`、`90` 是 **C 端订单列表的查询聚合虚拟状态**（仅作为 `ListOrders` 入参用于筛选，不落库、不参与状态流转）：`9` = 退款/售后聚合（7 + 8），`90` = 待发货聚合（2 + 3）。
- `100`（超时取消处理中）、`101`（自动完成处理中）是**调度器抢占中间态**，会在订单上短暂存在：处理失败立即回滚为原状态（1/4），进程异常中断场景由兜底扫描在 10 分钟后恢复，正常情况下用户不可见。

索引：`uni_orders_order_no(order_no)`、`idx_orders_user_id(user_id)`、`idx_orders_community_id(community_id)`

**refund_logs - 退款审批日志表**

记录退款单的审核/重试操作轨迹（谁在何时做了什么动作及备注），随订单服务 AutoMigrate 自动建表。

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | BIGINT UNSIGNED | 是 | 主键 |
| refund_id | BIGINT UNSIGNED | 是 | 退款单 ID |
| action | VARCHAR(20) | 是 | 动作：approve 同意 / reject 拒绝 / retry 重试 |
| operator_type | VARCHAR(20) | 否 | 操作者类型（admin / system） |
| operator_id | BIGINT UNSIGNED | 否 | 操作者 ID（0 表示系统自动操作） |
| remark | VARCHAR(255) | 否 | 备注（拒绝原因/重试结果等） |
| created_at | DATETIME | 是 | |

索引：`idx_refund_logs_refund_id(refund_id)`

汇算规则：单品应退 = item.total_price − item.total_price / order.total_amount × order.discount_amount（保留 2 位小数）；部分数量按比例计算；整单退时最后一行减法兜底尾差；用户调低金额的差额从最后一行明细扣减。
