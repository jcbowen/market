**status 值域补充说明**

- `9`、`90` 是 **C 端订单列表的查询聚合虚拟状态**（仅作为 `ListOrders` 入参用于筛选，不落库、不参与状态流转）：`9` = 退款/售后聚合（7 + 8），`90` = 待发货聚合（2 + 3）。
- `100`（超时取消处理中）、`101`（自动完成处理中）是**调度器抢占中间态**，会在订单上短暂存在：处理失败立即回滚为原状态（1/4），进程异常中断场景由兜底扫描在 10 分钟后恢复，正常情况下用户不可见。

索引：`uni_orders_order_no(order_no)`、`uni_orders_pickup_code(pickup_code)`（NULL 不参与唯一约束，允许多条配送单并存）、`idx_orders_user_id(user_id)`、`idx_orders_community_status_created(community_id, status, created_at)`、`idx_orders_delivery_status(delivery_user_id, status)`、`idx_shift_id(shift_id)`

> 存量库说明：早期版本 orders 表在 community_id 上建有单列索引 `idx_orders_community_id`，模型现已改用上述复合索引；GORM AutoMigrate 只增不删，该旧索引不会被自动移除，属冗余索引，可手动 `ALTER TABLE orders DROP INDEX idx_orders_community_id;` 清理。
